# CampaignManager.Migrate — перенос v1 → v2

Консольный инструмент T1.3: читает `games`/`identity` v1 сырым SQL (`row_to_json` → `JsonNode`, типов v1 нет),
пишет схему `cm` через `CmDbContext`, копирует объекты MinIO в бакет среды. Правила и таблица соответствий —
[SCHEMA.md](../../docs/v2/SCHEMA.md), «Перенос данных»; последний отчёт — [migration-report.md](../../docs/v2/migration-report.md).

## Запуск

```bash
# CM_DB — строка ветки Neon dev (та же, что в Server/appsettings.Development.json); прод сюда не подставлять
dotnet ef database update --project src/CampaignManager.Data          # схема cm должна догнать миграции
dotnet run --project tools/CampaignManager.Migrate -- --settings <файл> --reset --report docs/v2/migration-report.md
```

- **`--settings`** — JSON вне репозитория: `ConnectionStrings:Cm` (если нет `CM_DB`) и `Minio`: `Endpoint`,
  `AccessKey`, `SecretKey`, `Secure`, `SourceBucket` (боевой `campain-manager`, только чтение), `TargetBucket`
  (`campaign-manager-dev` для ветки dev). Собирать скриптом из `CampaignManager.Web/appsettings*.json` основного
  чекаута, не печатая. На проде (T3.2) источник и цель — один бакет, тогда объекты не копируются вовсе.
- **Повторный прогон на `dev`, когда объекты уже в `campaign-manager-dev`**: `SourceBucket` = `TargetBucket` =
  `campaign-manager-dev` и ключ 2.0 из `src/CampaignManager.Server/appsettings.Development.json` (у него права только
  на этот бакет, боевой он не читает). Перенос только сверяет объекты в цели — размеры и «не нашлось» те же.
- **`--reset`** — очистить всё в `cm`, кроме журнала миграций, и перенести заново. Без него непустая `cm` — ошибка.
- `--skip-files` — без MinIO (строки `files` заводятся без размера); `--keeper-time-zone` (по умолчанию
  `Europe/Prague`) — см. «Дата игры»; `--note` — строка в начало отчёта.
- Весь прогон — **одна транзакция**: упал шаг или проверка — `cm` остаётся, какой была. Объекты MinIO копируются
  до коммита, но копия идемпотентна (уже лежащий в цели объект не копируется второй раз).
- Ветку `dev` пересоздают от `main` перед прогоном: `npx neonctl@latest branches reset dev --parent --project-id
  old-wood-199224` — это стирает и `cm`, после сброса **сразу** `dotnet ef database update` (на `dev` живёт beta-стенд).

## Как устроено

| Файл | Что |
|---|---|
| `V1/V1Database.cs` | снимок v1 строками `JsonObject`, чтение полей (`Text`, `Guid`, `Enum` — v1 пишет enum'ы и именем, и числом) |
| `Migrator.cs` | порядок шагов, очистка, сохранение входа, проверки SCHEMA после вставки |
| `Steps/*` | люди → справочники → фонотека → кампании → сценарии → листы → состав НПС → история правок |
| `Catalogs/OwnerDecisions.cs` | решения владельца 2026-10-02 данными: современные предметы, повторы, реквизит, разделы |
| `Catalogs/SkillResolver.cs` | навык v1 по имени: справочник и старые написания (`SkillCodes`), «родитель (специализация)», языки |
| `Catalogs/OccupationSlots.cs`, `StatblockConverter.cs` | четыре поля профессии → слоты; четыре jsonb твари → `Statblock` |
| `Sheets/SheetConverter.cs` | лист v1 → `CharacterSheet` (не апкастер Core: нужен справочник) |
| `Files/FileStore.cs` | `CopyObject` на стороне MinIO из боевого бакета в бакет среды |

## Правила, которые легко сломать

- **Id v1 сохраняются** у всего, что переезжает один к одному (пользователи, кампании, сценарии, локации, проверки,
  листы, справочники, треки): ссылки, закладки и `ui.lastCharacterId` продолжают работать.
- **Код и имя книжной записи — из таблиц `Core/Catalogs/*Codes`**. Имя берётся из таблицы, а не из v1: там
  исправлены ошибки перевода (старое написание — вариант поиска). Навык без кода — ошибка переноса (исключение).
- **Современная эпоха убрана** (решение владельца): навыки и оружие с `Is1920 = false`, профессия с `IsModern`,
  53 предмета из `OwnerDecisions.ModernItems` не переносятся; у остального `eras = {Classic}`, `cost_modern` пуст.
  На листах навык только современной эпохи на базовом значении выбрасывается, выше базы — своя специализация
  или самодельный навык.
- **Лист**: в документ — только то, что вводит человек. У **НПС** расхождение вычисляемого с v1 — значение книги,
  оно уходит в `overrides`; у сыщиков и прегенов побеждает формула (решение владельца 2026-10-02: правильно по
  формуле, overrides не нужны), разница — в раздел отчёта «Листы: вычисляемое по формуле». «Пустые»
  значения v1 расхождением не считаются: максимум 0 (не заполнен), Рассудок max 99 и Рассудок max = текущему
  (книга печатает у НПС текущий Рассудок, v1 клал его в оба поля).
- **Текст граф «Фобии» и «Магические предметы» не переносится** (решение владельца 2026-10-02, T2.3): в 2.0 остаются
  только структурированные записи (фобии и мании, снаряжение). Листы, где графа была непустой, — раздел отчёта
  «Листы: отброшен текст граф…».
- Отметку развития у НПС ставил импорт сценария — у НПС она снимается целиком.
- **Тестовые листы с нулями** (`OwnerDecisions.TestSheetsCurrentToMax`, по id листа — сейчас один, «Адам
  Урбан-Фокс»): текущие ПЗ, ПМ, Рассудок и Удача = максимумы v1 в пределах формулы (`CharacterStep.FillCurrentToMax`).
  Точечная правка с разрешения владельца, не общее правило: ноль ПЗ у живого сыщика — состояние.
- Забронированный преген v1 → лист игрока (`Player`) в кампании ваншота, `scenario_id` пуст; брони не восстанавливаются.
- Тварь сценария — ссылка на бестиарий по имени; статблок сохраняется, только если отличается от бестиарного
  (сравнение канонического JSON Core); своё описание твари сценария (столбца нет) — в `notes`.
- Реквизит сценария из справочника v1 — предмет сценария без `item_id` с описанием из сценария.
- Раздатки с адресом-заглушкой `example.com` переносятся без файла.
- **Дата игры** (`Scenarios.ScheduledDate`, `timestamp without time zone`) — время «как ввёл Хранитель»; в UTC
  переводится из `--keeper-time-zone` (по умолчанию `Europe/Prague` — решение владельца 2026-10-02), смещение —
  на саму дату (летнее время); несуществующий час перевода стрелок сдвигается на час позже. Показ — в поясе
  браузера (T2.2).
- **Вход сохраняется при `--reset`**: перед очисткой запоминаются пользователи с `auth0_sub`; перенесённому
  пользователю с той же почтой возвращаются `auth0_sub` и время входа, а вошедший после v1 (beta) сохраняется как был.
- Почт в отчёте нет — только имена и названия.

## Тесты

`tests/CampaignManager.Migrate.Tests`: перевод листов на настоящих листах v1 (`Fixtures/Sheets`, обезличены: без
имени игрока и текстов биографии), правила справочников и сценариев на синтетических данных (тексты книги в
репозиторий не кладём, D5), прогон целиком на своей базе из `CM_TEST_DB` (`V1Fixture` — v1 только с нужными
колонками; `MigratorTests` — счётчики, решения владельца, перезапуск, отказ без `--reset`). Новый случай в данных v1 —
строка в `V1Fixture` и проверка в `MigratorTests`.
