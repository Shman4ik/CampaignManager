# Иллюстрации справочников — на сайт

Рисунки живут вне сайта: `X:\Knowledge\CallOfCthulhu\<что>-art\generated\classic\<имя>.png` (у бестиария —
`generated\<имя>-<вариант>.png`). На сайт их ставят двумя путями с одним и тем же сопоставлением файла и записи:

- **человек** — «⋯ → Загрузить картинки» на странице справочника под Хранителем (`UI/Catalogs/CLAUDE.md`, «Картинки пачкой»);
- **агент** — общий скрипт **`X:\Knowledge\CallOfCthulhu\upload_art.py`** (справка — его docstring и `--help`). Скрипты
  `upload_prod_files.py` в папках — обёртки над ним.

Под капотом оба делают одно: PNG → WebP 85, `POST /api/v1/files?format=webp`, `PUT /api/v1/catalogs/<справочник>/<id>/cover`
(у предмета и книги — их картинка, у остальных — первая в списке; API — `Server/Catalogs/CLAUDE.md`).

## Порядок

1. **Сверка, ничего не пишет:**
   `cd /x/Knowledge/CallOfCthulhu && uv run --with pillow --with requests python upload_art.py <папка> --dry-run`
   (прод; `--dev` — локальный сервер). Итог: «к загрузке N, пропущено (уже с картинкой или повтор) M, без записи K,
   варианты не-обложки V». Строки `NONE` — файл не нашёл запись: переименовать файл в код без префикса или дописать `code`
   записи в `art-prompts.json`. Строки `PLAN` — что будет загружено.
2. **Загрузка** — та же команда без `--dry-run`. По умолчанию — только записи без картинки; `--replace` — заменить стоящую
   обложку (перерисовали), `--only <имя> …` — выборочно. Долгую партию (100+) — фоновой задачей, ошибки — строками `FAIL`.
3. **Проверка** — повторная сверка («к загрузке 0») и страница справочника в браузере: картинки на карточках, раскрытие.

## Правила

- **На прод — только с явного разрешения владельца** (как и в `local-image-gen`). Сверка `--dry-run` на проде — только
  чтение, её можно всегда.
- **Прод — токен агента** (Auth0 M2M, `Server/Identity/CLAUDE.md`, «Токены агентов»): нужны scope'ы `files:write` и
  `catalogs:images`. Секрет — `~/.config/campaign-manager/agent.env`, не печатать; токен кэшируется в `token.json` рядом
  (у тенанта квота на выдачу). `PUT …/cover` отвечает 403 «нужен scope catalogs:images» — в кэше токен до выдачи scope:
  удалить `token.json`.
- **Dev — `--dev`**: сервер своего worktree на `https://127.0.0.1:8080` (`src/CLAUDE.md`, «Памятка исполнителя»), вход
  `/dev/login?as=keeper`. Бакеты dev и прода разные: залитое на dev на проде не появится. После сброса ветки Neon `dev`
  картинки нужно залить заново (2026-10-09 на `dev` не было рисунков у оружия и профессий).
- **Папка → справочник:** `items-art` → предметы, `books-art` → книги, `weapons-art` → оружие, `spells-art` → заклинания,
  `occupations-art` → профессии, `artifacts-art` → артефакты, `bestiary-art` → бестиарий (`creatures`); другая папка —
  `--catalog`. Файл → запись: по `art-prompts.json` (код, иначе название; у бестиария `<slug>-1` — обложка), иначе код без
  префикса из имени файла, иначе название без регистра и «ё».
- **Чего скрипт не делает:** портреты НПС (`npcs-art` — `PUT /api/v1/characters/{id}/portrait` с `If-Match`, лист
  персонажа токену закрыт: прежний путь из вкладки прода, папка `npcs-art`), дополнительные картинки записи (варианты 2+
  бестиария — в форме записи), подписи картинок.
- `prod-files.json` в папках — след прежнего двухшагового пути (файл токеном, запись — PUT из вкладки браузера), не нужен.

## Как это ломалось (не повторять)

- **PUT записи из вкладки прода** (до 2026-10-09): справочники токену были закрыты, и привязку делал `fetch` из открытой
  вкладки — 100+ записей в одном `javascript_tool` упирались в таймаут 45 с. Решено PR #283: узкий scope `catalogs:images`
  и `PUT …/cover`, полную запись справочника токену так и не открыли (решение владельца).
- **PNG по 2–3 МБ на сайте** — большая картинка раскрытой записи на iPad грузилась секундами. Теперь WebP 85 (предметы:
  193 МБ PNG → 18 МБ).
