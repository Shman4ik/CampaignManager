([migration-report.md](migration-report.md)). Проверка — на трёх копиях схемы `cm` в локальном Postgres
(по одной на группу), под dev-входом от имени перенесённых людей (роль = роль в базе). Три исполнителя на
Sonnet: (а) 1, 2, 11; (б) 3–6 и лечение вне боя (T2.3b); (в) 7–10. Вьюпорт 1366×1024 — проходом,
1024×1366 и 390×844 — замером ширины страницы и тап-целей. Вёрстку здесь не оценивали — это аудит UX
(метка `ux`, [UX-REVIEW.md](UX-REVIEW.md)).

## Наблюдения без issue

- Неверное значение enum в теле `POST/PUT /api/v1/campaigns` даёт 500 вместо 400 (ошибка биндинга); из UI
  не воспроизводится.
- «Бой» и «Погоня» в меню 2.0 видит только Хранитель; в v1 пункты и страницы были у любого вошедшего.
- Перенесённая заявка на Хранителя «Одобрена», а роль у человека — игрок (так было в v1, см. `Admin/CLAUDE.md`).
- Журналов встреч в v1 нет (`campaign_sessions` пуста) — чтение перенесённого журнала проверить не на чем.
- У перенесённых раздаток нет картинок, у локаций нет музыки — так и в v1.

## Осталось человеку

- Вход через Google целиком (согласие Auth0), вход по паролю, выход с гашением сессии Auth0, автовход с
  настоящей кукой.
- Настоящий iPad (Safari): громкость через Web Audio, первый звук касанием, перемотка, «Включить звук» для
  YouTube, касания строк навыков, автосохранение в нестабильной сети, два устройства на одном листе.
