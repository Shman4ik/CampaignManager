# UX-REVIEW — план правок по аудиту UI/UX 2.0

Решение владельца: **чинить всё до переключения прода (T3.2)**. Приоритет — вёрстка и плотность, согласованность,
тексты. Правила — [docs/design-system.md](../design-system.md), раздел «Правила 2.0 после аудита» (ссылки «п. N»
ниже — на его пункты). Аудит — 48 issue с меткой `ux` (#144–#191); #168 и #170 в списке нет (их пометки не заводились).
Карточки в `TASKS.md` заводит оркестратор.

по чек-листу аудита на 1366×1024, 1024×1366 и 390×844.

## Волна UX-1 — страницы по группам

В каждой группе первыми идут пункты «**мешает играть**»; дальше — из того, что волна UX-0 не закрывает.
Подробности по каждому пункту — в тексте issue (чек-лист по строкам).

### U1 — оболочка, главная, вход, кампании, кабинет, админка (#144–#155)

1. **Мешает играть:** главная — блок «Ваншоты — открыта запись» выше «Ваших кампаний» и занимает весь первый экран; «Открыть лист» ниже (#145). Порядок: кампании игрока → открытые записи сжатой строкой.
2. **Мешает играть:** страница кампании 390×844 — подпись «Имя в этой кампании · с 6 апреля» схлопывается в колонку 40px; перестроить строку участника (#148).
3. Завершённая кампания — свёрнутая строка с одним «Журнал»; «Создать сыщика», «+ НПС», «Исключить» только у активных (п. 17; #145, #147, #148).
4. «Удалить кампанию»/«Выйти из кампании» из первого места в «Опасную зону» внизу; «Исключить» — в «⋯» (п. 7; #147, #148, #149).
5. Журнал встреч: окно 745×842 в `Large` с вкладками/шагами, «Изменить» + «Удалить» в `RowMenu`, пустое состояние строкой, одна «Новая встреча» (#149).
6. Кабинет: «Роль» и «Мои игры» — без дубля бейджа, «Выйти» один (п. 16; #150).
7. Заявки/пользователи/файлы: подпись «Сейчас: игрок» → «Роль: игрок», «Сироты» → «Файлы без записи», отдельный текст пустой вкладки заявок (#151–#153).
8. 404 и «Нет доступа» — текст по политике страницы; `/about`, `/legal` — ответить осмысленно до T3.2 (#154, #155).
9. `/login` и окна «Новая кампания», «Вступить», «Имя в кампании»: фокус, ширина, подсказка про ваншот только при пустом поле, ошибка у поля (#146–#148).
10. `<title>` каждой страницы группы и подпись рельса (п. 5, 15; #144–#155).

### U2 — лист сыщика, помощник, создание, `/npcs` (#156–#164)

1. **Тап-цели и «Убрать навык» 20×20, галочка развития 18×18, −/+ у ПЗ 36×36** (п. 1; #158, #157).
2. Один паттерн «добавить» на листе: встроенная панель для справочника, окно для кубиков; убрать «Вручную» и дубли «Из справочника»/«+ Предмет» (п. 6; #159, #160).
3. Корзина строки оружия/заклинания/предмета — сразу + тост «Отменить»; «Новый день» и «+5 к Мифам» — с предпросмотром итога (п. 7; #159, #160).
4. Мелкий текст: 63% узлов ≤ 12px — шапки столбцов оружия, числа ½/⅕, подсказки до 13px; абзацы — в «Как это работает» (п. 2; #156–#161).
5. «(стр. N)» из заголовков шагов помощника, опций и таблиц — в `BookRef` (п. 10; #162).
6. Жаргон листа: МКН/МКП/ЗМ, Б.К.У., Комп., Скор., Укл., «Бросить» у «Случайный сыщик», «Блиц», «Род занятий» → «Профессия» (п. 11; #158, #160, #162, #163).
7. Disabled без причины: «Записать приступ», «Записать» (фобия), «Применить к листу», «Добавить» (специализация), «Записать неделю»; «Лечение» при полных ПЗ — не показывать (п. 8; #157, #158, #160).
8. Одна `primary` в окне «Фаза развития» и на шаге 2 помощника; окно «Фаза развития» — шаги или вкладки, высота фиксирована (п. 3; #158, #162).
9. Заголовок листа «Лист сыщика: Имя» + подзаголовок (кампания, статус); `<title>` по шаблону; «Новый сыщик» называет кампанию (п. 5, 15; #156, #162, #163).
10. «Выйти» в помощнике → «Отменить создание»; «НПС»/«Преген» в `/npcs` → «Добавить НПС», «Добавить готового сыщика» (п. 6; #162, #164).

### U3 — сценарии (#165–#173)

1. **Мешает играть:** «Новый сценарий» меняет адрес, но окно не открывается (нет подписки на `LocationChanged`) — #165.
2. **Мешает играть:** режим игры — «Проверки» начинаются на y≈984 из 1024, раздатки на 6741px правой колонки, «Кто проверяется» по умолчанию «вписать вручную» при четырёх сыщиках (п. 14; #171).
3. **Мешает играть:** окно раздатки — битая картинка (`<ImagePicker Url="_fileUrl">` без `@`) — #169.
4. Пустые вкладки и «Что внутри» из нулей — строка вместо карточки 110–250px; нули не показываем (п. 4; #166–#169, #171).
5. Одна кнопка и «⋯» в строках локаций/проверок/фактов/раздаток вместо «Изменить + Удалить»; «Удалить сценарий» — в «Опасную зону» (п. 7; #165–#169, #173).
6. Кнопки добавления с глаголом: «Добавить локацию/проверку/факт/раздатку», «Добавить из бестиария», «Добавить предмет» (п. 6; #167, #169).
7. Окна сценария: фокус, ширина `Medium`/`Large`, ошибка у поля, `FilePicker` вместо «Choose File» (п. 3, 9, 17; #165–#173).
8. Одно название на объект: «Описание» = «Изменить описание» = окно; «Факты» = «Ключевые факты»; «Результат проверки» вместо «Пробный прогон» (п. 3, 11; #166–#169).
9. Строки списка — раскрываются касанием; бейдж-повторы и цвета по смыслу; заголовок секции, повторяющий вкладку, убрать (п. 5, 17; #167, #169).
10. Второй экран раздатки: «Закрыть» 44px, фокус, подпись; `/edit` — «Отмена» без потери молча (#172, #173).

### U4 — бой, погоня, ширма, фонотека, плеер (#183–#191)

1. **Мешает играть:** результат/предпросмотр эффекта и атаки вне экрана (п. 14: `scrollIntoView`, фокус, результат в блоке кнопки) — #183, #184, #188.
2. **Мешает играть:** «Кто атакует» после «Применить» показывает не того (#184).
3. **Мешает играть:** мёртвый сыщик (ПЗ 0) блокирует «Начать погоню» без объяснения; «Начать погоню» может сразу закончить погоню без предупреждения; сбежавшие помечены «выбыл» и «Вернуть» (#187, #188).
4. **Мешает играть:** ничего не липнет, строка участника 151–174px, список 1490px; колонка действия `sticky`, строка ≤ 64px, внутренняя прокрутка, журнал под шапкой (п. 14; #183, #187).
5. «Убрать»/«Удалить» в каждой строке (8 красных кнопок, 25 в фонотеке) → «⋯»; «Завершить» отделить от «Следующий» (п. 7; #183, #187, #190, #191).
6. Пустые панели до первого участника не рисуются; форма «Действие» без селектов; disabled «Записать»/«Бросить за всех» с причиной (п. 4, 8; #183, #185, #187).
7. Высота вкладок боя и окна «Участник сцены» фиксирована; кнопка действия не прыгает при вводе (п. 3, 14; #185, #186, #187).
8. Тексты записей: шаблоны без склонения, `1d6`, метки одного регистра, «Вступили: …» одной записью, «Завершить бой?» (п. 13; #183–#188).
9. Шапка боя и погони: убрать «Музыку боя/Музыку», блок «Ширма» + «Плеер» с разными иконками (п. 16; #183, #187, #189, #191).
10. Плеер: 2 кнопки с подписью, остальные в «⋯», сворачивание после «Остановить», громкость ≥ 44px; фонотека — «⋯» в строке, окна одной ширины, «Изменить трек» (#190, #191).

### U5 — справочники (#174–#182)

1. **Мешает работать:** ошибка валидации не видна — прокрутка к ошибке, красные рамки, все ошибки сразу, `*` обязательных (п. 9; #174, #176, #177–#182).
2. **Мешает работать:** правка существа — `Сохранить` только внизу страницы 2255px, ошибка вверху; закрепить подвал страницы (#176).
3. Картинка записи: `ImagePicker Url="item.ImageUrl"`/`b.ImageUrl` без `@` — битая миниатюра у предметов и книг (#178, #180).
4. Эпоха «Наши дни» — скрыть, пока `ErasVary` ложно (п. 12; #174, #177, #181, #182).
5. «««Бентли»»» — имя без обрамляющих кавычек в `ConfirmationModal`, тостах, `ApiErrors` (п. 7; #174, #177–#180).
6. Словарь справочников: «Бестиарий», «Сбросить фильтры», «Дальность», «Атаки за раунд», «Потеря Рассудка», `1d6`, «—» (п. 11, 13; #174–#182).
7. Сокращения БкУ, МКН/МКП/ЗМ, ПМ/МОЩ, «Дист.» — полными словами или `Abbr` (п. 11; #175, #177, #180, #182).
8. Таблицы: не обрезать название и тип, раскрытие с отступом и `?open=`, пагинация вне карточки; профессии — 12 на страницу (п. 17; #177–#182).
9. Перенос данных до T3.2: цена предметов в отдельное поле, составные типы заклинаний в справочник, «Динамитная шашка*», «Источник» у оружия (#177–#179).
10. Миниатюры бестиария `?w=480`; игроку — статблок или нет (вопрос 1 ниже) (#175).

## Что нельзя делать параллельно

- **UX-0 целиком — одному исполнителю подряд.** Общие файлы: `Shared/Button.razor`, `Modal.razor`, `ModalWindow.razor(.js)`, `PageHeader.razor`, `EmptyState.razor`, `Field.razor`, `DialogService.cs`, `ToastService.cs`, `Styles/components.css`, `Styles/shell.css`, `Layout/*`. Две ветки на них дают конфликты и разные соглашения.
- **UX-1 стартует после слияния UX-0**; страницы без новых компонентов (чисто тексты) можно начать раньше, но не `PageHeader`/`Modal`.
- **Группы UX-1 между собой почти независимы** — у каждой своя папка (`Campaigns|Admin|Profile`, `Characters`, `Scenarios`, `Encounters|KeeperScreen|Music`, `Catalogs`) и свой CSS (`sheet.css`, `scenario.css`, `encounter.css`). Исключения:
  - **`Checks/` (диалог проверки, групповая проверка)** используют U2 (лист) и U4 (бой, погоня) — один исполнитель, U2 раньше U4 или U2 передаёт U4.
  - **`Catalogs/CatalogPickerModal`, `StatblockView`** подключаются из U2 (лист), U3 (сценарии, «Из бестиария») и U4 (участник боя) — U5 владеет файлами, остальные ждут слияния U5 по этим файлам или правят только свои вызовы.
  - **`Layout/NavMenu` и подписи рельса** — U1; U4 (`Фонотека`) и U5 (`Бестиарий`) ничего в `Layout/` не трогают, сообщают U1 текст.
  - **Плеер в шапке** — `PageHeader` (UX-0) + `Music` (U4); U4 не редактирует `PageHeader`.
  - **`Styles/components.css`** правят только в UX-0; группы — свои файлы стилей.
  - **Словарь замен** (`Terms`/`CatalogText`) — один владелец (UX-0), группы добавляют строки отдельными коммитами; конфликтует по одному файлу.
  - **Данные и перенос** (#177–#179, п. «Цена в отдельное поле») — `tools/` и `Data`; не параллельно с правкой моделей `Contracts`.
- **Страница `Scenarios` и `Encounters`** связаны режимом игры (бой из сценария): U3 и U4 по `Scenarios/Play*` и `Encounters/*Shell*` согласуют границу заранее.
- **Сверка** (повторный аудит по `ux-checklist`) — только после слияния всех групп.
