# Оркестратор 2.0

Как сессия-оркестратор ведёт карточки [TASKS.md](TASKS.md) через исполнителей (subagent в своём
worktree). Памятка самого исполнителя — [src/CLAUDE.md](../../src/CLAUDE.md), «Памятка исполнителя».

Составлено 2026-10-02 по итогам волн 1–2 (PR #108–#137): 32 запуска исполнителей стоили ≈13 млн
токенов, и большую часть можно было не тратить. Ниже — что из этого следует.

## Правила

1. **Модель по задаче.** Opus — карточки с правилами книги и нетривиальной логикой (лист, бой,
   погоня, перенос). Sonnet — UI без правил, правки, документация, проверка паритета. Haiku —
   поиск по коду. Параметр `model` у Agent ставить явно.
2. **Решения — до запуска.** Прочитать карточку, собрать вопросы к владельцу, запустить исполнителя
   уже с ответами. Решения, пришедшие после запуска, — переделка.
3. **Карточка — до 100–150 вызовов инструментов.** Крупную делить на части с отдельными PR: цена
   сессии растёт быстрее числа шагов, каждый шаг перечитывает весь контекст.
4. **Общие документы правит оркестратор** после слияния: «Сделано» в TASKS.md, паритет в README,
   сводные таблицы `src/CLAUDE.md`. Исполнитель пишет их в раздел PR «Для TASKS/README». Так
   параллельные PR не конфликтуют друг с другом.
5. **Перебазирование — оркестратор сам** (`git rebase`, конфликты в документах — вручную) или
   свежий исполнитель на Sonnet. Не продолжать старого исполнителя: продолжение поднимает весь его
   контекст (перебазирование T2.2 стоило 560 тыс. токенов).
6. **Промт короткий:** шаблон ниже. Не «прочитай CLAUDE.md всех модулей», а конкретные файлы.
7. **Слияние** — только после зелёного `build-and-test` (набор правил «Require CI» на `master`,
   автослияние в репозитории выключено): `gh pr checks <N> --watch`, затем
   `gh pr merge <N> --squash --delete-branch`. Несколько PR — одной фоновой командой по очереди.
8. **Уборка** — только worktree своих исполнителей, по имени (`agent-<id>`), только при пустом
   `git status --short`. Чужие worktree (сессии владельца) не трогать.
9. **Перед запуском** — `git pull --ff-only` в основном чекауте: worktree создаётся от локального HEAD.
10. **Свой контекст держать маленьким:** большие файлы — по разделам, отчёты не пересказывать
    целиком. Когда контекст за ~300 тыс. — новая сессия с передачей состояния (раздел ниже).

## Шаблон промта

```
Ты делаешь CampaignManager 2.0, задача <ID> «<название>».
Прочитай: docs/v2/README.md («Правила для сессий»), src/CLAUDE.md («Памятка исполнителя» и
<нужные разделы>), карточку <ID> в docs/v2/TASKS.md, <конкретные CLAUDE.md модулей>, <разделы AUDIT/SCHEMA>.

Решения владельца: <список или «нет»>.
Порт <порт>, контейнер <имя>:<порт>. Параллельно идут: <задачи, их порты>.

Готово: build -warnaserror без предупреждений; dotnet test зелёный с CM_TEST_DB; <сценарий проверки
в браузере>; CLAUDE.md модуля обновлён; в PR — раздел «Для TASKS/README».
PR один, от master, не черновик, на русском; после создания — mcp__ccd_pr__get_status.
Решение владельца не угадывать — вопрос в PR и в ответе.
Ответ: ссылка на PR; что сделано; отличия от карточки; вопросы.
```
