# CampaignManager 2.0 — задачи

Каждая карточка — задание на одну сессию. Сначала прочитай [README.md](README.md) (решения,
архитектура, правила для сессий), потом свою карточку и разделы, на которые она ссылается.
Статус решений D1–D7 — в README. Если карточка зависит от решения со статусом «предложено» —
остановись и спроси владельца.

Формат карточки: **Цель** · **Зависит от** · **Входы** · **Шаги** · **Готово, когда** ·
**Не потерять**.

### T1.2 — Схема `cm` в `Data`

**Сделано 2026-10-01.** `CmDbContext` со всеми 34 таблицами SCHEMA.md по модулям (`Data/Identity`,
`Files`, `Campaigns`, `Catalogs`, `Music`, `Scenarios`, `Characters`, `Encounters`, `Admin`), миграция
`InitialCmSchema` применена на пустом Postgres 17 и на ветке Neon `dev` (PostgreSQL 15.19; v1 не тронут).
`Server.Tests/Schema` поднимают схему в своей одноразовой базе и проверяют владельца листа, членство
игрока, один активный лист, `SET NULL (campaign_id)`, одного Хранителя, CHECK из enum, `lower(name)`,
одну активную сцену (`NULLS NOT DISTINCT`), `xmin`, перехватчик времени и совпадение модели с миграцией.
Правила работы со схемой — [src/CLAUDE.md](../../src/CLAUDE.md), «База». Отличия от карточки:
- enum'ы колонок положены в `Core/<Модуль>` (их возьмут `Contracts` и документы T1.7);
  `Era`, `Characteristic`, `Difficulty` — в корне `Core`: если T1.7 заведёт свои, оставить одну копию;
- `DataProtectionKey` — стандартная сущность пакета, `CmDbContext` реализует `IDataProtectionKeyContext`;
- defaults в DDL есть, но EF их не использует (`HasDbDefault`): иначе «нулевое» значение подменялось бы
  default'ом базы;
- расхождения миграции с текстом DDL (CHECK у `eras`, индексы на FK, `xmin` у `music_tracks`) записаны
  в SCHEMA.md под «DDL».

**Цель.** `CmDbContext` и первая миграция по SCHEMA.md.

**Зависит от:** T1.1, T0.1, D3.

**Шаги.**
1. Сущности и конфигурации по модулям; `UseSnakeCaseNamingConvention()`; схема по умолчанию `cm`,
   журнал миграций — `cm.__ef_migrations_history` (не общий `public`, на котором v1 уже обжёгся).
2. Хелпер: CHECK для перечисления генерируется из самого enum.
3. `xmin` как `Version` у корней из SCHEMA, правило 8; перехватчик `created_at`/`updated_at`.

5. Частичные индексы, `NULLS NOT DISTINCT`, `ON DELETE SET NULL (campaign_id)` — `migrationBuilder.Sql`.
6. `dotnet ef migrations script` → сверить с DDL в SCHEMA.md. Расхождение исправляется в коде
   или, если SCHEMA ошибся, в SCHEMA — с объяснением в PR.

**Готово, когда** миграция применяется на пустой базе и на ветке `dev`; `Server.Tests` поднимают

### T1.3 — Перенос данных v1 → v2

**Сделано 2026-10-02.** `tools/CampaignManager.Migrate`: v1 читается `row_to_json` в `JsonNode`, `cm` пишется
через `CmDbContext` одной транзакцией, `--reset` очищает `cm` (кроме журнала миграций) и переносит заново, после
вставки — проверки SCHEMA (один Хранитель, нет сирот `files`); каждый лист прочитан типами Core. На ветке `dev`,
сброшенной от `main`, перенос проходит и перезапускается с теми же счётчиками; объекты MinIO (212 строк `files`,
≈650 МБ) скопированы внутри MinIO в новый бакет `campaign-manager-dev`. Отчёт — [migration-report.md](migration-report.md),
знание — [Migrate/CLAUDE.md](../../tools/CampaignManager.Migrate/CLAUDE.md), тесты — `tests/CampaignManager.Migrate.Tests`
(листы v1 обезличенные + прогон целиком на `CM_TEST_DB`). Решения владельца 2026-10-02 выполнены: современная
эпоха выброшена (39 оружия, 3 навыка, «Хакер», 53 предмета; из таблиц кодов Core тоже), 3 повтора гостиниц
выброшены, 4 реквизита стали предметами сценария «Среди древних деревьев», ошибки перевода исправлены в именах
таблиц кодов (15, старое написание — вариант поиска), «Фотоаппараты» → «Развлечения». Отличия от карточки и SCHEMA:
- `Era.Modern` в enum и колонки эпох **оставлены**, миграции нет: на `Era.Modern` держатся правила финансов
  современности (`FinanceRules`, тесты T0.2), а данных с ним после переноса нет; фильтр эпохи в UI решает T2.1;
- статблок Core получил необязательные `attacks[].description` (у всех 153 атак v1 есть текст) и `skills[].note`
  — без них перенос терял бы текст; версия документа та же;
- навык листа без справочника — свой навык листа (`name`), а не новая строка `skills`; языки без родителя
  («Латынь», «Язык (французский)») — специализации «Язык, иностранный»; написания с листов v1 («Фотография»,
  «Наука судмедэксперт»…) добавлены вариантами в `SkillCodes`;
- у НПС `overrides` не считают расхождением «пустые» значения v1 (максимум 0, Рассудок 99 и равный текущему);
  у сыщиков и прегенов вычисленное побеждает, 7 расхождений — в отчёте (решение владельца 2026-10-02: правильно
  по формуле, overrides не нужны); тестовому «Адаму Урбан-Фоксу» текущие ПЗ/ПМ/Рассудок/Удача из нулей подняты
  до максимумов точечно, по id листа; отметки развития у НПС сняты (126);
- раздатки с файлом (2) — заглушка `example.com`, перенесены без файла; своё описание твари сценария — в `notes`;
- `sha256` у перенесённых файлов пуст (объекты не скачивались); 3 картинки тварей v1 ссылаются на несуществующие
  объекты — ссылки не перенесены (в отчёте);
- дата игры ваншота переведена из пояса `Europe/Prague` (параметр `--keeper-time-zone`; решение владельца
  2026-10-02, было московское);
- `--reset` сохраняет вход: пользователь с `auth0_sub` (beta) получает его обратно, вошедший после v1 — остаётся.

**Цель.** `tools/CampaignManager.Migrate` по SCHEMA.md, «Перенос данных».

**Зависит от:** T1.2, T1.7 (типы документов), T1.5 (строки `files`), T0.1.

**Шаги.** Таблица соответствий и правила для мусора — в SCHEMA.md. Перезапускаемый (`--reset`),
отчёт — `docs/v2/migration-report.md` в PR. Перевод листа v1 → документ 2.0 — в `Migrate`, а не
в `Core`: ему нужны справочник навыков и старые написания имён. Тесты — на реальных листах
(обезличенных: имена персонажей можно, почты нельзя).

**Сиды (D5).** Если для тестов и чистых сред нужны справочники, в репозиторий идут только
названия, коды и числа. Описания и тексты книги остаются в базе.

**Коды справочников** — только из явных таблиц `Core/Catalogs/*Codes` (решение владельца 2026-10-02):
`SkillCodes`, `OccupationCodes`, `WeaponCodes`, `SpellCodes`, `BookCodes`, `ItemCodes`, `CreatureCodes`,
поиск — `FromName` (без учёта регистра, «ё» и лишних пробелов). Код — английское название книги 7e в
kebab-case с префиксом справочника (`skill.dodge`, `occupation.private-investigator`, `weapon.thompson`,
`creature.deep-one`); у навыков специализация — `skill.<родитель>.<специализация>`
(`skill.firearms.handgun`). Не транслит и не вычисление из имени. Написания v1 на листах («Языки
(родной)», «Вождение», «Автомат», «Стрельба (винт./дроб.)»…) таблица навыков тоже знает. Строка
справочника v1, которой нет в таблице, переносится с `code` null и **попадает в отчёт**: самодельное
(перечислено в комментарии в конце таблицы) — ожидаемо, всё прочее — повод дополнить таблицу. У
всех 93 навыков справочника v1 код есть — навык без кода считается ошибкой переноса.

**Готово, когда** перенос на свежей ветке `dev` проходит без ошибок, счётчики сходятся с
ожидаемыми из SCHEMA, отчёт перечисляет всё отброшенное.

**Цель.** Один обобщённый каталог вместо семи ручных: 15,4 тыс. → ~7,7 тыс. строк (AUDIT,

**Входы.** AUDIT, «Справочники»; `CLAUDE.md` фич Weapons, Items, Spells, Books, Skills, Bestiary;

**Шаги.**

3. **`CatalogPage<T>` + `CatalogDefinition<T>`:**
   - колонки, сортировки, фильтры (поиск, enum, эпоха, флажки);
   - «колонка прячется, когда фильтр фиксирует её значение»;
   - `CanExpand`, порог таблицы (замерить по числу колонок, как в v1), форма, флаги прав.
   - Вид «таблица + карточки»; бестиарий — вид «галерея» (`?open=`).
4. **Описания каталогов:** навыки (детали навыка — один компонент, им же пользуется справка на

   строка остаётся текстом, как обещают комментарии; поменять ожидание теста с `finding` F-P13.

## Волна M. Мобильное

### M1 — PWA

**Цель.** Веб ставится на экран «Домой» iPad и iPhone и открывается как приложение.

**Зависит от:** T3.2 (можно и раньше, на 2.0 до переключения).

**Шаги.** Манифест, иконки (включая `apple-touch-icon`), `apple-mobile-web-app-*`, service worker
с кэшем оболочки и версией сборки (новая версия — обновление по кнопке, а не тихо посреди игры).
Безопасные отступы (`env(safe-area-inset-*)`) для выреза и полосы «Домой».

**Готово, когда** установленное с экрана «Домой» приложение на iPad открывается без адресной
строки, а после деплоя предлагает обновиться.

### M2 — Раскладки для телефона

**Цель.** Игрок пользуется 2.0 с iPhone: главная, свой лист (просмотр и правка), помощник
создания, проверки и кости, журнал кампании, раздатки.

**Зависит от:** T2.2, T2.3, T2.4, T2.5, T2.7.

**Шаги.** Вьюпорт 390×844 (и 430×932). Экраны Хранителя (сценарий, бой, погоня) на телефоне не
обязаны быть удобными, но не ломаются и не прокручиваются вбок.

### M3 — Живой стол

**Цель.** Хранитель показывает раздатку — она появляется на телефонах игроков. Изменения листа и
сцены видны на других устройствах без перезагрузки.

**Зависит от:** T2.3, T2.5, T2.6.

**Шаги.** SignalR-хаб `TableHub` на сервере (группы по кампании), события «раздатка показана»,
«лист изменён», «сцена изменена». Клиент — в `ApiClient`, чтобы им пользовалось и мобильное
приложение. Второй экран раздатки (`/scenarios/{id}/handouts/{handoutId}`) остаётся статической
страницей — телевизору у стола хаб не нужен.

### M4 — Приложение на Avalonia

**Цель.** Нативное приложение для iPhone и iPad на том же API (D4).

**Зависит от:** T3.2, M3 (по желанию).

**Шаги.**
1. `mobile/CampaignManager.Mobile` (Avalonia, iOS; Android — по желанию) на `Core` + `Contracts` +
   `ApiClient`. UI свой, на XAML; начать со сценариев игрока из M2, а не со всего приложения.
2. Вход — Auth0 для нативного приложения (PKCE, системный браузер через
   `ASWebAuthenticationSession`, своя URL-схема), токены — в Keychain. В Auth0 — отдельное
   приложение типа Native (делает владелец).
3. Проверить `Core`/`Contracts`/`ApiClient` под AOT на iOS — именно ради этого они с T1.1
   собираются с `IsAotCompatible`.
4. CI: `macos-latest` (публичный репозиторий — бесплатно), подпись и TestFlight — аккаунт Apple
   Developer владельца.

**Готово, когда** игрок входит с iPhone, видит свой лист, бросает проверку и получает раздатку.
