# CampaignManager.Core — правила книги и документы

Чистый C#: кости, правила «Зова Ктулху» 7e, документы (лист, статблок, сцена), разборщики строк книги.
Без EF, ASP.NET, Blazor, HTTP — общий с WebAssembly и мобильным приложением (D4), поэтому
`IsAotCompatible` + `IsTrimmable`, JSON только через `CmJsonContext`. Страницы — книга Хранителя,
русское издание. Знание перенесено из `CLAUDE.md` фич v1 `Characters`, `Combat` (кости), `Weapons`,
`Spells`, `Bestiary`; обходы v1 (circuit, хранимые производные, совместимость со старым JSONB) — нет.

**Одна копия формулы.** Любая формула книги живёт в одном месте Core и покрыта тестом в
`tests/CampaignManager.Core.Tests`. Если правило понадобилось в UI или на сервере — звать его, а не
считать на месте: в v1 копии в разметке расходились с правилами (AUDIT, «Правила в разметке»).

Enum'ы колонок схемы здесь же (T1.2): CHECK в миграции строится из членов. Новый член enum'а колонки —

документов (`InsanityBoutMode`, `MythosBookStage`, `CreatureAttackKind`…), миграции не трогают — в JSON
они именем, переставлять члены можно, переименовывать — нет.

## Кости

- **Случайность — параметром** (`IDiceRoller`), а не статикой: `DiceRoller.Shared` за столом,
  `SeededDiceRoller` для повтора, в тестах — `ScriptedDice`. Генератор отдаёт сырые кости: грань
  `1..N` для `Die`, `0..9` для d100 (сначала единицы, потом каждая кость десятков).
- **Любой бросок можно вписать** — правило листа v1, его требование, а не удобство. Правило, которое
  бросает, принимает `IDiceRoller`; окно с полем «Выпало» подставляет вписанное (`D100.RollOrEntered`
  или `EnteredDiceRoller`: вписанный d100 (`Percentile`) и суммы NdM (`Total`, раскладывается по граням) идут первыми
  по порядку бросков правила; невписанное — пустой слот, его бросает генератор). Кости шагов фазы развития —
  `DiceSpec`-константы `DevelopmentPhaseRules` (`SkillGain`, `MasterySanity`, `LuckGain`, `SelfHealingGain`,
  `CreditRatingDice`): по ним окно предлагает вписать сумму, а правило бросает — одна копия.
- **d100** (стр. 89): одна кость единиц и 1 + |нетто| костей десятков; бонусная гасит штрафную;
  «00» + «0» = 100, поэтому выбор по итогу, а не по кости десятков.
- **Уровень успеха — только `Check.Evaluate`** (стр. 80, 86–89). 01 — всегда критический, 100 —
  всегда крах; 96–99 — крах, если для успеха нужно меньше 50, и при трудной/чрезвычайной проверке
  это половина/пятая значения (стр. 88). Уровень — от полного значения, сложность решает только,
  пройдена ли проверка (`Check.Passes`). Проверка ВЫН, ИНТ, Рассудка — тоже через неё: в v1 13
  инлайнов `roll <= value` расходились с функцией на 01 и 100.
- `SuccessLevel` (что выпало) отдельно от `Difficulty` (что требовалось). Критической сложности у
  проверки нет; нарастающая очередь (стр. 114) моделирует «невозможно» сама (T2.6).
- **Формула костей — только `DiceFormula`**: латинская и русская «d/д», типографские минусы, пробелы,
  константы. Разбор снисходительный, как в v1 (`1D6+БкУ` бросает 1d6), `IsValid` говорит, что что-то
  пропущено. `Max` — каждая кость на максимальной грани, у вычитаемой тоже («-1d4» → −4).

## Документы

- Документ — `record`-ы без поведения, все наследуют `DocumentPart`: неизвестные поля ложатся в
  `Extra` и возвращаются при записи **на любом уровне вложенности**. Вычисляемые свойства документа —
  `[JsonIgnore]`, иначе уедут в JSON.
- JSON: camelCase, enum'ы именами, `null` не пишется (`CmJsonContext`). Новый тип документа или DTO
  черновика — `[JsonSerializable]` в `CmJsonContext`.
- **Версия — в колонке** (`*_version`), текущая — `CurrentVersion` типа. Читать только через
  `CmJson.Read…(json, version)`: старая версия 2.0 проходит шаги `DocumentUpgrader` над JSON до
  десериализации. Новая версия: поднять `CurrentVersion`, добавить шаг в `DocumentUpgrader.Steps`
  (тест проверяет, что шаг есть у каждой версии ниже текущей). Документ новее приложения читается как
  есть — незнакомое доживает в `Extra`.
- **Листы v1 апкастер не переводит** (версия 0 — исключение): это делает перенос T1.3, ему нужны
  справочник и сопоставление навыков по имени.
- `Data` хранит документы как `JsonDocument` — сознательно: апкастеру нужна версия из соседней колонки,
  а конвертер EF её не видит; и изменённый на месте граф EF без глубокого сравнения не заметил бы
  (та же ловушка, что с JSONB в v1). Сервис читает `CmJson.ReadSheet`, применяет правила и
  присваивает `CmJson.Write(...)`.

## Лист сыщика (`CharacterSheet`)

- **В документе только то, что вводит человек.** Максимумы ПЗ/ПМ/Рассудка, Удача max = 99,
  Комплекция, БкУ, Скорость, Уклонение считает `DerivedAttributeRules.Compute`; половину и пятую —
  `CharacteristicMath`. Напечатанные у НПС значения из книги — `Overrides`, они побеждают формулу
  (иначе импорт терял ПЗ и БкУ из книги).
- **Навык — ссылка на справочник**: `{ skillId?, name?, parentSkillId?, value, checked }`. `value` —
  полное значение (база внутри). `name` — только у своего навыка и у специализации, которой нет в
  справочнике (тогда это уточнение в скобках: «латынь», а родитель — `parentSkillId`). Группы не
  хранятся — берутся из `skills.category`. Поэтому лист без `SkillCatalog` не читается, и правила
  принимают его параметром.
- **Навыки правил — по коду**, не по имени: `SkillCodes` (Мифы, Средства, Уклонение, языки, родители
  с общим прогрессом, социальные). `sheet.Value(catalog, code)` — строка листа или база
  справочника; `EnsureEntry` заводит строку, если навыка на листе нет, а в справочнике есть.
- **Код навыка — английское название книги** (Call of Cthulhu 7e) в kebab-case: `skill.dodge`,
  `skill.cthulhu-mythos`, `skill.credit-rating`, `skill.language-own`. **Специализация — код родителя,
  точка и английское название специализации**: `skill.fighting.brawl`, `skill.firearms.handgun`,
  `skill.science.biology`, `skill.language-other.english` (`SkillCodes.ParentOf` отрезает последний
  сегмент). Код не вычисляется из русского имени: соответствие — явная таблица в `SkillCodes` (на `CatalogCodeTable`)
  (93 навыка справочника v1, только названия и коды, D5). `SkillCodes.FromName` ищет по имени
  справочника и написаниям v1 («Языки (родной)», «Вождение», «Автомат»…) без учёта регистра, «ё» и
  лишних пробелов. Перенос (T1.3) и сиды берут коды только оттуда. Самодельный навык (и специализация,
  которой нет в таблице, — «латынь») — `code` null. Новый книжный навык — строка в таблице; выданный
  код не меняется, тест проверяет формат, уникальность и родителей.
- База навыка — число справочника или `base_formula`: `DEX/2` у Уклонения (стр. 57), `EDU` у родного
  языка (стр. 77) — `SkillCatalog.BaseValueOf`. Своё Уклонение-зеркало в листе не хранится.
- Оружие на листе — текст книги (урон, дальность, атаки, патроны, осечка); числа — `WeaponStatsReader`
  при каждом чтении. Разобранных блоков в листе нет: в v1 они не пересчитывались после правки, и бой
  бросал устаревший урон.
- Заклинание и книга Мифов на листе — свой экземпляр (`catalogSpellId`, `bookId`): экземпляры книг
  различаются (стр. 222), правка на листе не трогает справочник.
- **Биография** — графы бланка, ключевая связь, раздельные «Предыстория» и «Заметки». Текстовых граф «Фобии» и
  «Магические предметы» нет (решение владельца 2026-10-02): фобии и мании — `InsanityConditions`, предметы —
  `Equipment`; текст этих граф в старых документах доживает в `Extra`, перенос его отбрасывает.
- **Раскладка навыков листа** — `SheetSkillLayout`: группы бланка, базовые навыки справочника видны и без строки
  (значение — база), специализации на базе свёрнуты под родителем; правки строк (`SetValue` заводит строку,
  `AddFromCatalog` — с базой, а не с нулём, как в v1; `AddSpecialization`, `AddOwn`, `Remove`, `SetChecked`).
- **Копии справочника в лист** — `SheetCopies.Weapon`/`Spell` (своя копия: правка на листе справочник не трогает).
- Слепок, черновик и предпросмотр — `CmJson.Serialize`/`DeserializeSheet`/`Clone(лист)`.
- Деньги — `decimal?`; активы — словами (`FinanceRules.WealthTier.AssetsText`, у нищего «нет»).
  `TryParseMoney` v1 остался только переносу.
- Время в документе — `DateTimeOffset` UTC; правила принимают `now` параметром (по умолчанию — сейчас).

## Правила листа

- **Удача** (стр. 93, 97): потолок всегда 99, а не стартовый бросок. Крах и критический успех не
  выкупаются; трата — только `LuckRules.Spend`. Успех, купленный Удачей, **за этот бросок** отметки развития
  не даёт; отметку, которая уже стоит на навыке от других бросков, трата **не снимает** (решение владельца
  2026-10-02 по книге). `Spend` снимает только отметку, поставленную за этот же бросок (`markOfThisRoll`), —
  в v1 диалог листа снимал любую, диалог проверки — никакую. Уровень с порогом 01 не продаётся: 01 — всегда критический, а его Удачей не покупают (F-S03, исправлено в T2.7).
- **Рассудок** (гл. 8): два окна потерь — `lastSanityLoss` (одна причина, ≥5 → проверка ИНТ, стр. 153)
  и `sanityLostToday` (день, ≥⅕ Рассудка **на начало дня** → бессрочное, стр. 154). Порог ⅕
  округляется **вверх** (52 → 11). Складывать окна нельзя: два провала по 3 проверки ИНТ не дают.
  Списание — только `SanityRules.ApplyLoss` (одна причина за вызов); прибавка — `Grant`. Исход проверки ИНТ —
  `ResolveIntCheck` (успех — временное безумие и приступ; оба исхода гасят подсказку); всё, что показывает панель
  рассудка, — `Status` (панель ничего не считает сама).
- **Привыкание к ужасному** (гл. 8, стр. 167) — `HabituationRules`: запись по виду (тот же вид второго счётчика не
  заводит), предел — максимум провальной части потери, потеря не больше остатка и списывается через `ApplyLoss`.
- **Флаг «положен приступ»** (`condition.boutDue`) ставят и снимают только `SanityRules`: отметка
  безумия (любое безумие начинается с приступа, стр. 154) и любая потеря в затаённом безумии
  (стр. 156); снимают запись приступа, «без броска» и снятие обеих отметок. Флаг, а не вывод из полей.
  Текст приступа в лист не копируется — по номеру его отдают `InsanityTables`.
- **Таблицы главы 8** (`InsanityTables`): номера строк — как в русском издании, чтобы бросок
  настоящими костями находил ту же строку; строки 9–10 ведут к фобиям и маниям. Описания — пересказ,
  не цитата (D5).
- **Мифы**: максимум Рассудка = 99 − Мифы (стр. 153); `AddMythos` прижимает текущий. Безумие от Мифов:
  первый случай +5, следующие +1 (стр. 160–161); случай засчитывается, только если прибавку записали.
- **Книги Мифов** (стр. 171–174): МКН за начальное чтение; МКП за полное, пока Мифы читателя ниже ЗМ,
  иначе снова МКН; каждое следующее полное изучение вдвое дольше. Стадию двигает только
  `MythosBookRules.Apply` (стадия руками для прочитанного до игры — `SetStage`, без эффектов); потеря рассудка приходит числом (окно не применяет её без числа); порядок —
  сначала потеря с текущего, потом новый максимум прижимает остаток. Неверящий теряет 0, Мифы растут
  (стр. 177).
- **Фаза развития** (стр. 92–94, 164–167): проверка опыта — 1d100 больше навыка **или** выше 95,
  +1d10, может перейти 100%; впервые 90% — +2d6 Рассудка. Мифы и Средства не отмечают. Удача:
  1d100 больше текущей — +1d10 до 99. Самолечение — проверка Рассудка (`Check`), ключевая связь даёт
  бонусную кость и лечит бессрочное, при провале теряется. Средства — семь вариантов (1d100 у
  «Банкрота» — грань 1..100); деньги после смены — к остатку наличных прибавляется столбец «Наличные».
  Привыкание снижается на 1. Набор отмеченных навыков окно снимает один раз на открытие.
- **Специализации** (стр. 76–77): +10 смежным на порогах 50 и 90, не выше порога. Список родителей
  закрытый, по коду: ближний бой, стрельба, иностранный язык, выживание — книга прямо
  противопоставляет им Науку.
- **Раны** (стр. 117–120) — **один конвейер `WoundRules` для листа и сцены** (T2.6b, схема получения урона ширмы,
  стр. 119) над `WoundStatus` (ПЗ, серьёзная рана, без сознания, при смерти, стабилизирован, мёртв); лист и снимок участника
  только читают и пишут свои поля (`WoundRules.Read/Write`, `EncounterParticipants.Wounds/SetWounds`):
  - урон одной атаки **≥ максимума ПЗ — мгновенная смерть** (граница «равно» — смерть: F-S02, решение владельца по
    официальному тексту 7e; русский перевод в списке стр. 118 пишет «больше» — ошибка перевода, см. rules-findings);
  - ≥ половины максимума с округлением вверх (13 → 7) — серьёзная рана: валит с ног, проверка ВЫН (исход приходит
    параметром — бросок вписывает или бросает тот, кто зовёт), провал — без сознания;
  - 0 ПЗ без отметки — без сознания; с отметкой — при смерти (и без сознания). Дальнейший урон при 0 не пишется, новая
    рана снимает стабилизацию;
  - первая помощь: умирающему — временная стабилизация (1 ПЗ, «при смерти» остаётся), остальным +1 ПЗ и сознание;
    Медицина: +1d3 и сознание, умирающему — только после первой помощи, тогда «при смерти» снято; ВЫН умирающего: не
    стабилизирован — в конце раунда, провал — смерть; стабилизирован — в конце часа, провал — снова при смерти;
    недельное лечение серьёзной раны — ВЫН (кости за уход, отдых, плохие условия): успех 1d3, чрезвычайный 2d3 и отметка
    снята; без раны — 1 ПЗ в день;
  - лечение руками (`Heal`) мёртвых не поднимает; правка ПЗ на листе (`UpdateConsciousness`/`Settle`) смерть не снимает.
  `SheetCondition.Dead`/`Stabilized` добавлены без смены версии: в старом документе их нет — значит, false.
- **Создание** (гл. 3): возраст 15–90 (книга); строки таблицы — до «80–89», возраст вне таблицы получает **ближайшую**
  строку (90+ — «80–89», меньше 15 — «15–19»; F-S01, исправлено в T2.4; в v1 — «Молодой»). Штраф Скорости — `MovePenalty`
  той же строки (`ComputeMoveRate` его не дублирует); вычет за возраст
  игрок распределяет сам между целями строки; НАР и ОБР — фиксированные штрафы; проверки ОБР —
  1d100 > ОБР → +1d10 до 99. Очки профессии: если формула даёт выбор, берётся **выбранная**
  характеристика, а не максимум (стр. 38–39). Личные — ИНТ × 2.
- **Профессии** (стр. 37–39): ровно 8 профессиональных навыков плюс Средства. Слоты — из схемы
  (`OccupationSlotDefinition`), `OccupationRules.BuildSlots` раскладывает их для помощника: названные →
  выборы → социальные → свободные, Средства последними, Мифы не покупаются. Вариант-родитель выбора
  разворачивается в специализации и даёт вписать свою; соседние слоты группы делят пул
  (`ChoiceGroup`). Названная книгой специализация, которой нет в справочнике, — Fixed с родителем: её
  надо добавить на лист (`NewSpecialization`, база — у первой соседней, иначе 1%), иначе навык пропадёт.

## Конструктор листа (`SheetBuilder`, T2.4)

- **Один конструктор вместо пяти v1**: `Blank`, `FromDraft` (помощник), `QuickNpc`, `FromImport` (файл сценария, T2.5d);
  случайный сыщик — `RandomDraft`: черновик помощника, заполненный бросками тех же правил и открытый на «Итоге» (D6.4),
  дальше тот же `FromDraft`. Листы неотличимы по устройству — тест `SheetBuilderTests` (одни имена навыков и производные).
- **Навыки — только ссылки на справочник**, строка заводится, только если значение **выше** базы (`SkillCatalog.IsAboveBase`;
  строка, которая ничего не добавляет к справочнику, — `SheetSkills.AddsNothing`, им же чистит листы перенос T1.3).
  Ниже базы строки нет тоже: «Язык, родной: 0» из файла сценария (листы v1, где 0 — «не заполнено») перекрыл бы ОБР. Родной язык (`EDU`)
  и Уклонение (`DEX/2`) — формулы справочника, строк для них нет. Свой навык — строка с именем; специализация вне
  справочника — с родителем (`OccupationRules.NewSpecialization`). Специализации на базе лист показывает свёрнутыми
  под родителем (решение владельца по T2.3) — конструктор строк для них не заводит.
- Производные — `DerivedAttributeRules.InitializeNewSheet` (ПЗ и ПМ на максимуме, Рассудок = МОЩ); Удача — из черновика.
  `FromImport`: напечатанные ПЗ, ПМ, БкУ, Комплекция, Скорость, расходящиеся с формулой, — `Overrides`; Уклонение выше
  базы — строка навыка; Рассудок книги — текущий; имя навыка — `SkillNameResolver` (написания v1, «Родитель (уточнение)»,
  языки без родителя), не нашлось — свой навык и строка отчёта. Отметки развития импорт не ставит (в v1 — всем).
  Сверх v1 — графы биографии, оружие (навык по имени), заклинания, снаряжение, деньги. Обратное — `ToImport` (экспорт
  сценария): итоговые производные, навыки только выше базы, Уклонение полем; `FromImport(ToImport(x))` даёт тот же
  `ToImport` — на этом держится кругооборот файла сценария (тест).
- **Помощник над черновиком** — `CreationPlan`: слоты (`OccupationRules.BuildSlots`), ключи навыков (`Id` строкой или
  уточнение своей специализации), бюджеты, база и итог, лимит 75% (вариант, стр. 46), блиц (Средства — одно из девяти
  значений), проверки шагов (`Validate`, `FirstInvalidStep`). Правки шагов «Способ» и «Характеристики» — методы
  `InvestigatorDraft` (`SetAge`, `SetCharacteristic` сбрасывает проверки ОБР, `AddEducationCheck(dice)` — вписанное через
  `EnteredDiceRoller`, `SetLuckRolls` — лучший бросок, `AvailableFor` — один алгоритм набора на вариант 3 и блиц).
  Набор варианта 3 не сортируется: первые пять мест — 3d6, остальные — 2d6 + 6 (так вписывают кости по месту).
- **Быстрый НПС** — `QuickNpcRules` (гл. 10): типажи с навыками **по коду**, опытность 25/40/70, оружие из справочника
  поднимает свой навык (по `SkillId` оружия, без сопоставления имён), драка добавляется всегда. Имена — `NameTables`
  (одна таблица по эпохам на быстрого НПС и случайного сыщика; эпоха — поле, а не разбор текста).
- `BiographyTables.Section` читает и пишет свою графу (`Read`/`Write`/`Append`), бросок по списку — `Entry(table, roll)`.

## Коды справочников (`Catalogs/*Codes`)

- **Код книжной записи — английское название в книгах Chaosium для 7e** в kebab-case с префиксом
  справочника: `skill.`, `occupation.`, `weapon.`, `spell.`, `book.`, `item.`, `creature.`
  (`occupation.private-investigator`, `weapon.38-or-9mm-revolver`, `spell.summon-bind-byakhee`,
  `creature.deep-one`). Апострофы, точки калибров и звёздочки книги пропадают (`Gla'aki` → `glaaki`).
  Иерархия (`родитель.специализация`) — только у навыков, см. выше.
- **Соответствие — явная таблица на справочник**, не транслит и не вычисление: `CatalogCodeTable`
  (код, имя справочника v1, старые написания). `FromName` ищет без учёта регистра, «ё» и лишних
  пробелов; null — записи нет в таблице, то есть она самодельная. В таблице только названия и коды (D5).
- **Самодельное без кода**: в таблицу не попадает, его имена v1 перечислены комментарием в конце таблицы.
- **Где официального названия нет или источники расходятся** — выбрано ближайшее, у строки комментарий
  «спорно: …». Источники сверки — в описании PR, который ввёл таблицы.
- **Выданный код не меняется**: переименовать запись — правка имени (и строки таблицы), а не кода;
  синхронизация с правилами (T2.1) и перенос (T1.3) ищут по коду. Новая книжная запись — новая строка.
- **Ошибка перевода в имени v1** («Флаг (1 метр)» у фляги) исправляется в имени строки, а старое написание
  уходит в варианты поиска: `new("item.canteen", "Фляга", ["Флаг (1 метр)"])`. Перенос (T1.3) берёт имя записи
  из таблицы, поэтому исправление доходит до `cm`.
- **Современной эпохи в таблицах нет** (решение владельца 2026-10-02): записи только современной эпохи
  (39 единиц оружия, 3 навыка, «Хакер», 53 несверенных предмета) убраны; их коды больше не выдаются. Сам
  `Era.Modern` остаётся — на нём правила финансов современности (`FinanceRules`) и колонки схемы; данных с ним нет.
- Тесты (`SkillCodesTests`, `CatalogCodesTests`): у каждой строки код с префиксом и в kebab-case, коды и
  имена уникальны, поиск по написаниям работает, самодельные имена дают null.
- **Сид профессий** (`OccupationSeed`, T2.1) — для «Синхронизировать с правилами»: код, формула, Средства,
  слоты именами навыков справочника (код — `SkillCodes.FromName`; «Родитель (специализация)», которой нет в
  таблице, — `ResolveSkill` даёт родителя и «латынь»). Средств в слотах нет; у каждой ровно 8 навыков (тест).
  Только числа и названия (D5). Современных профессий нет — как и в таблице кодов.
- **Подписи перечислений справочников** — `CatalogText.Of(…)` (категория навыка, эпоха, тип оружия и твари,
  категория книги, формула профессии, вид слота, вид атаки, БкУ атаки) и `CatalogText.Damage(атака)`. Одна
  таблица на приложение: в разметке своих словарей не заводить.

## Разборщики (`Catalogs`)

- `DamageFormulaParser` — колонка «Урон»: кости, плоская прибавка, бонус к урону (полный/½, все
  написания из данных), эффекты, дробовик по дальностям, взрывчатка с радиусом. Всё, что понимает
  `DiceFormula`, понимает и он. Эффект без костей («Шок») формулой не считается и остаётся текстом —
  F-P13 исправлена в T2.1; при костях эффект разбирается («2d6+горение»).
- `WeaponStatsParser` — дальность, атаки, боезапас, стоимость, осечка; совпадает с тем, что v1 записал
  в каталог (тесты по всем значениям каталога). Осечка «00» = 100, одиночный «0» — пусто.
- `SpellStatsReader` — подсказка стоимости и времени сотворения из текста, а не правда: неразобранное
  остаётся пустым, Хранитель подтверждает. `SpellMatcher` — только точное совпадение после
  нормализации, без нечёткого поиска.
- `SanityLossFormula` — «успех/провал»; предел привыкания — максимум провальной части, тем же
  разбором, что и бросок.

## Проверки (`Checks`)

- Цель проверки — `CheckSubject` (вид, имя, значение, коды навыка и родителя), собирает её `CheckSubjects` с
  листа; ключ `skill:{id справочника}`/`char:STR`/`luck` одинаков на листе любого сыщика. Проверка локации
  сценария — ссылка (`CheckTarget`, навык, характеристика), не имя: `Resolve`/`KeyFor`.
- `CheckRules` — что разрешено после броска (повтор, Удача, отметка; стр. 82–97, запреты боя — стр. 102),
  уровни — только `Check`. Ближний бой и Стрельба узнаются по коду (F-C09 закрыта устройством).
- **Диалог лист не пишет**: решение игрока — `CheckSheetChange`, его применяет владелец документа
  `CheckRules.Apply`. Трату собирает `CheckRules.LuckSpend`: если диалог уже отметил навык за этот бросок
  (успех отметили, потом подняли Удачей), в изменение кладётся `UndoMarkOfThisRoll`, и `Apply` передаёт эту
  строку в `LuckRules.Spend` — снимается только своя отметка. `Mark` вместе с тратой Удачи не ставится.
  Стоявшая до броска отметка остаётся. Знание UI — `UI/Checks/CLAUDE.md`.
- Лучший в групповой проверке — `GroupCheck.Best` (в v1 жил в разметке).

## Ядро сцены (`Encounters`, T2.6a)

Общее для боя и погони. В v1 было два движка одного вида (AUDIT, «Сцены»); здесь одно ядро, бой (T2.6b) и погоня (T2.6c)
добавляют к нему свои правила, эффекты и виды записей.

- **Участник — ссылка плюс снимок чисел** (`EncounterParticipant`): `SourceCharacterId` / `SourceCreatureId`, сторона,
  характеристики и производные (`ParticipantStats`), ПЗ/ПМ/Рассудок/Удача, рана и сознание. **Id участника ≠ id листа.**
  Снимок — `EncounterParticipants.FromSheet` (правила листа: `DerivedAttributeRules`, максимум Рассудка с Мифами) и
  `FromStatblock` (инициатива 0 — по ЛВК; рассудка и Удачи у твари нет). У листа истина — лист: `Refresh` после записи.
- **`EncounterEngine.Add`**: один лист — один раз (отказ с текстом), тварей — сколько угодно, «#1», «#2» по источнику
  (имя, данное Хранителем, не трогается).
- **Очередь — `EncounterQueue`** по id активного (`ActiveParticipantId`), порядок раунда — `TurnOrder`, строится в начале
  раунда по инициативе, затем ЛВК, затем порядку добавления. Удаление уже ходившего не сдвигает ход (F-C04, F-P03),
  выбывший не сдвигает ход посреди действия (F-P04), отложивший отдаёт ход следующему (F-C03), отложенное — только на
  этот раунд (F-P05). Новичок посреди раунда встаёт по инициативе; если его место прошло — ходит со следующего.
- **Резолв возвращает эффекты, применяет их один `Apply`.** `EncounterResolution` — заголовок, строки, эффекты
  (`EncounterEffect`: плоская запись с видом `EncounterEffectKind` — урон, лечение, ПМ, потеря рассудка, МОЩ, выбывание).
  `Propose` кладёт результат в документ (`Pending` — переживает перезагрузку), `Preview` считает «было → станет» тем же
  кодом на копиях, `Apply` — единственное место, где эффекты меняют участников; он же пишет журнал и ставит эффекты
  участников с листом в `SheetWrites`. «Отменить» — `Cancel`: выбросить, менять нечего (F-C02 закрыта устройством).
- **Итог в лист — `EncounterSheetEffects.Apply(лист, справочник, эффекты)`** правилами листа: урон — `WoundRules.ApplyDamage`
  (та же серьёзная рана и сознание, что у снимка: `WoundRules.Consciousness`), лечение до максимума, ПМ в пределах,
  рассудок — одна причина через `SanityRules.ApplyLoss`, от твари — через `HabituationRules` по виду (`CreatureName` без
  номера), МОЩ навсегда с прижатием ПМ. Эффект — приращение: при 409 лист перечитывают и применяют снова. Пишет UI
  (`UI/Encounters/EncounterSheetSync`) через API листа; заблокированную запись (`Blocked`) решает Хранитель.
- **Журнал типизирован**: `EncounterLogEntry` с видом `EncounterLogKind` (имя в JSON), строками и раундом; подписи и
  категории (цвет) — одна таблица `EncounterText`, тест требует подпись у каждого члена. Хранится последние
  `MaxLogEntries` (500). Новый вид записи или эффекта — член enum'а + строка `EncounterText` + ветка в `EncounterEngine`
  (и `EncounterSheetEffects`, если пишется в лист).
- Раны участника и листа — один `WoundRules` (см. «Правила листа»): мгновенная смерть, серьёзная рана с ВЫН, при смерти,
  стабилизация (T2.6b, F-S02).
- Тесты: `Core.Tests/Encounters` — `EncounterQueueTests` (исправленные F-C03/F-C04/F-P03/F-P04/F-P05),
  `EncounterEngineTests` (снимок, «#N», один лист, предпросмотр и отмена, Apply и очередь записей, раны, журнал, JSON),
  `EncounterSheetEffectsTests` (раны, лечение, ПМ и МОЩ, рассудок и ИНТ, привыкание по виду).

## Таблица модификаторов атаки (`Encounters/AttackModifiers`)

Бонусные и штрафные кости атаки (стр. 105–114) — **таблица** строк (`AttackModifierRule`: вид атаки, бонус
или штраф, сколько костей в обстоятельствах `AttackSituation`, причина, когда положено, страница, пример).
`Calculate` складывает кости Хранителя и все положенные строки (гасит их бросок d100). Её читают бой (T2.6b
строит `AttackSituation` из участников) и памятка ширмы — разойтись им не из чего. Новый модификатор — строка
с примером; тест требует, чтобы пример давал ровно эту строку. Ожидания — тесты T0.2 на
`CombatService.CalculateAttackModifiers` (`Core.Tests/Encounters`). Там же `NormalizeSurprise` (в стрельбе
автопопадания нет), `HasNumericalSuperiority`, `RequiredDifficulty` по дальности.

## Ширма (`KeeperScreen`)

Таблица III «Другие виды урона» с падением и ядами (`OtherDamageReference`), примеры потерь рассудка

## Бой (`Encounters/Combat`, T2.6b)

Правила главы 6 на ядре сцены; знание — из `Combat/CLAUDE.md` v1 и тестов T0.2 (перенесены в `Core.Tests/Encounters/Combat`).

- **Правило разрешает, `Apply` применяет.** `CombatRules.Melee/Ranged/Maneuver/CastSpell/SanityCheck/FirstAid/Medicine/
  DyingCheck/WeeklyRecovery/TakeCover/…` возвращают `EncounterResolution` (или `AttackOutcome`/`SpellOutcome` — тот же
  результат плюс числа для подписей и тестов) и **ничего не меняют**: ход, атаки и защиты раунда, прицел, патроны,
  заклинивание, захват — эффекты (`EncounterEffectKind.Attack`, `Defense`, `Ammo`, `Jam`, `Grapple`…), их применяет
  `CombatEffects.Describe` из `EncounterEngine.Apply`. «Отменить» не тратит ничего (F-C02). Без предпросмотра — только
  броски инициативы и переключатели необязательных правил (`CombatSettings`).
- **Любой бросок вписывается**: d100 — `D100Roll?` в настройке (вписанный — `D100Roll.Entered`), сумма — `int?`; не пришло —
  бросает `IDiceRoller`. Порядок бросков правила: атака, защита, урон, БкУ, проникающая, ВЫН (тесты держат его скриптом).
- **Уровни — только `Check`** (F-C06 исправлено: ВЫН и ИНТ v1 шли `roll <= value`). Крах стрельбы — от сложности дальности
  (стр. 88); требование «критический» у очереди — для порога краха сложность чрезвычайная (`DifficultyOf`).
- **Кости атаки — `AttackModifiers`** (таблица T2.7, её же читает ширма): `MeleeDice`/`RangedDice` собирают `AttackSituation`
  из участников; прицел и укрытие — «из настройки или из состояния, один раз». Нарастающая очередь — `EscalateAutofire`
  (штрафные — строкой таблицы), размер очереди — `VolleySize` (навык/10, не меньше 3).
- **Что умеет участник — `CombatProfile`** (снимок, `CombatProfiles.FromSheet/FromStatblock`, его же обновляет `Refresh`):
  драка (1D3 + БкУ) у каждого листа; оружие листа — навык **по ссылке** `SkillId` (значение строки или база справочника:
  листы на `dev` хранят только навыки выше базы); дальний — по коду Стрельбы/Метания (без навыка — по дальности в метрах);
  проникающее — огнестрел всегда, остальное по отметке справочника (эвристика имён v1 «нож/пик…» не перенесена: «Пикап» у
  неё был проникающим); БкУ — `DamageBonusOf` («без бонуса» в данных не переопределяет). Твари — атаки статблока и атак за раунд.
- **Что с ним в бою — `CombatantState`**: счётчики раунда помечены раундом (`Touch`, `AttacksIn/DefensesIn/AutofireIn`) —
  новый раунд обнуляет их сам, очереди про бой знать не нужно; укрытие — раунд, потеря атаки — раунд; прицел живёт до
  выстрела (любого — F-C07), раны или движения; огнестрел наготове — +50 в `EncounterQueue.Order` (при бросках инициативы —
  бонусная кость, а порядок — по уровню броска, потом ЛВК; новичок без броска считается провалом).
- **Ближний бой**: встречная проверка, ничья при уклонении — защитнику, при контратаке — атакующему; защита считается
  только у цели начеку и только если атакующий не провалил; беззащитная цель — попадание, кроме краха; контратака-победа
  ранит атакующего (без максимума за чрезвычайный). **Стрельба**: без встречной, дальность — сложность, осечка (≥ порога,
  1d6 раундов починки вписываются), шальная пуля при крахе в ближнем бою — союзнику стрелка с наименьшей Удачей (у тварей
  Удачи нет), проникающая на сверхдальней — только при критическом. **Манёвр**: Комплекция 3+ — невозможен (ход не
  тратится), меньше — штрафные кости; «Вырваться» освобождает вырвавшегося (F-C08); нокаут — только с правилом.
- **Заклинания**: первое сотворение сыщика — трудная МОЩ, провал — цена без эффекта, повторная — срабатывает с ценой
  ×(1 + 1d6); нехватка ПМ — урон по ПЗ тем же конвейером ран; МОЩ навсегда; рассудок с ИНТ; у твари рассудка нет. 2+ раунда —
  `SpellCasting` на участнике, рана его срывает (`Disrupted`), «сработало» или «срыв» — `CompleteCasting`/`InterruptCasting`
  (срыв платит только ПМ и рассудок). Встречная МОЩ — `OpposedPower`, разница 100+ — без броска. Эффект на цель —
  «Эффект Хранителя».
- **Проверка Рассудка**: без бонусных костей, крах — максимум провала, 5+ — ИНТ; исход ИНТ едет в эффекте (`Check`), а лист
  решает сам: после привыкания потеря могла стать меньше 5 — тогда ИНТ не нужна. Пороги ⅕ и ноль — `SanityRules.Status`.
- **Медицина**: первая помощь и Медицина действуют раз на рану (флаги в `CombatantState`, сбрасывает новый урон); первая
  неудачная попытка делает следующую повторной. Кому положена ВЫН в конце раунда — `DyingChecksDue` (первая — в конце
  **следующего** раунда после «при смерти»).
- Тесты: `Core.Tests/Encounters/Combat` — перенесённые `Damage`, `MeleeAttack`, `RangedAttack`, `Maneuver`, `SanityCheck`,
  `SpellCast`, `Round` (кроме очереди — она в `EncounterQueueTests`), новые `Medical` (пример с Харви) и `CombatProfiles`;
  раны — `Sheet/WoundRulesTests` (тест на ветку схемы, граница «равно максимуму»). `SkillLookupTests` v1 не переносились —
  сопоставления имён нет.

## Погоня (`Encounters/Chase`, T2.6c)

Глава 7 (стр. 128–149, книга Хранителя) на ядре сцены; знание — из `Chase/CLAUDE.md` v1 и тестов T0.2 (перенесены в
`Core.Tests/Encounters/Chase`, расхождения с книгой — `docs/v2/rules-findings.md`, F-P01…F-P18).

- **Состояние — `EncounterState.Chase` (`ChaseState`)**: этап (`Setup → SpeedCheck → Active → Ended`), трасса (`ChaseLocation`:
  номер с 1, название, `ChaseHazard`/`ChaseBarrier`), бегущие (`ChaseRunner` по id участника: роль, локация, способ и своя
  СКО, поправка проверки скорости, действия/остаток/долг, атаки раунда, транспорт `ChaseVehicle`, пассажир водителя
  `CarrierId`, штурман, разгон `ChaseBoost`, статус), самая медленная СКО, переключатели части 5, очередь внезапных помех,
  решённые ничьи ЛВК. Числа людей (ЛВК, ВЫН, СКО, ПЗ, Комплекция, своя СКО плавания/полёта, атак за раунд) — из снимка
  участника (`ParticipantStats.Swim/Fly/AttacksPerRound` добавлены для погони).
- **Ядро зовёт погоню само** (минимальные стыки, `state.Chase is not null`): `EncounterEngine.Add/Remove` → `ChaseRules.OnAdded/
  OnRemoved` (новичок посреди погони — присоединение, стр. 140: ждёт проверки скорости), `EncounterQueue.Start/NewRound` →
  `OnRoundStarted` (действия перемещения), `EncounterEngine.Apply` → `AfterApply` (побег и конец), `Describe` → `ChaseEffects`.
  Поэтому общие кнопки оболочки («Следующий», «Выбыл/Вернуть», «Убрать») погоню не ломают.
- **Правило разрешает, `Apply` применяет**: `ChaseActions.*` возвращают `ChaseOutcome` (результат + бросок, уровень, успех) и
  ничего не меняют; изменения — эффекты погони (`ChaseMove`, `ChaseActionsSpent/Lost`, `ChaseSpeed`, `VehicleBuild`,
  `BarrierDamage`, `PlaceObstacle`, `ChaseBoost`, `NavigatorAssist`, `ChaseAttack`, `Escaped/Caught/LostTrail/TooSlow`) — ветка
  `ChaseEffects`. Урон людям — общий `Damage` (раны и запись в лист — один конвейер `WoundRules` с боем; в v1 погоня считала
  только «ПЗ после»); 0 ПЗ — ещё эффект `Out` (выбыл из погони). Мимо `Apply` — только настройка Хранителя (роль, транспорт,
  пассажир, место, способ передвижения, трасса) и броски ничьей ЛВК.
- **Уровень — от полного навыка** (`Check.Evaluate`), сложность помехи/преграды решает только, пройдена ли проверка (F-P01).
  Кости проверки — одна функция `ChaseActions.ActionDice` и для правила, и для поля броска на экране: бонусные за осторожность
  у помехи (≤ 2, стоят действий), штрафные разгона, поломки транспорта (стр. 143), стрельбы на ходу и шины, разницы Комплекции
  манёвра. Объявленные кости идут и в автобросок. Встречная проверка — `CombatRules.AttackerWinsOpposed` (одна копия с боем).
- **Начало (стр. 130, 145)**: убегающий быстрее самого быстрого преследователя сразу уходит, преследователь медленнее самого
  медленного убегающего отстаёт (`TooSlow`); расстановка — по книге: самый медленный преследователь на 1, остальные впереди
  на разницу СКО, самый медленный убегающий — на отрыв (2, бывает 1) впереди самого быстрого преследователя, остальные — на
  разницу (в v1 все преследователи на 1, все жертвы на 3 — F-P14); трасса удлиняется, если не хватило места.
- **Действия (стр. 132–133)**: 1 + (СКО − самая медленная); долг потерянных действий съедает следующий раунд; при выбывании
  самая медленная СКО не пересчитывается (стр. 140), при присоединении и смене СКО — пересчёт, действия раунда меняются на
  разницу (потраченные не возвращаются). Пассажир — без проверки скорости и действий, ходит в порядке ЛВК, едет с водителем.
- **Что можно в ход — только `ChaseRules.AvailableActions`**: помеха и преграда лежат в **следующей** локации; перед помехой
  «вперёд» — это «пройти помеху» (проходят всегда, провал — урон и 1d3 потерянных действий), перед преградой — преодолеть
  или сломать (если есть ПЗ); летящему можно и над ними (стр. 142); бой, манёвр, таран — в одной локации, огнестрел — куда
  угодно; свои по машине — не цели; атак за раунд — как в бою; разгон без новых действий; пассажир — стрельба, штурман,
  помеха; спрятаться — убегающему, искать след — преследователю; «Педаль в пол» — с правилом части 5.
- **Транспорт** (`VehicleRules`): урон — полные десятки снимают Комплекцию, остаток **не учитывается** (стр. 136, 143; v1
  копил остаток, F-P07 пересмотрена по книге); таран и разрушение — 1d10 за пункт **своей** Комплекции (F-P06), отдача тарана —
  половина урона, не больше Комплекции цели; поломка на половине — штрафная кость к управлению (F-P15); потеря ≥ полной
  Комплекции за раз — «вдребезги» (подсказка Хранителю). Авария (таблица VI, по умолчанию по сложности помехи) — Комплекция и
  та же кость урона каждому внутри; шина — броня 3, штрафная кость за размер (и ещё одна на ходу, F-P17).
- **Побег и конец**: одна локация с убегающим — не поимка (`Catch` объявляет Хранитель); убегающий на последней локации впереди
  всех преследователей или когда гнаться некому — сбежал сам; все убегающие вне погони — `Ended`. «Спрятаться» — Скрытность
  (на транспорте один бросок должен пройти и Вождение, F-P08).
- **Разгон «Педаль в пол»**: объявил 2–5 локаций — свободные проезжает сразу, перед помехой встаёт (её проходят со штрафными
  разгона без нового действия, провал обрывает разгон), перед преградой разгон кончается (в v1 разгон перепрыгивал всё, F-P16).
- Тесты: `Core.Tests/Encounters/Chase` — `ChaseParticipantTests`, `ChaseSpeedTests`, `ChaseObstacleTests`, `ChaseVehicleTests`,
  `ChaseTurnTests`, `ChaseOptionalRulesTests` (перенос T0.2 с правкой ожиданий только по книге).
