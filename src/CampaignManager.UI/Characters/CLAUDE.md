# Characters (UI) — лист сыщика

Страница `/character/{id}` (T2.3) на документе листа Core (`CharacterSheet`). Данные — только `ICharactersApi`
(`Contracts/Characters`) и справочники `ICatalogApi<T>`; права решает сервер
([Server/Characters/CLAUDE.md](../../CampaignManager.Server/Characters/CLAUDE.md)), UI прячет правку по `CanEdit`.
Знание перенесено из `CampaignManager.Web/Components/Features/Characters/CLAUDE.md` v1 (раскладка листа, рассудок,
книги Мифов, фаза развития, сохранение); обходы v1 — `[PersistentState]`, снимки пререндера, `IDbContextFactory`,
хранимые производные, зеркало Уклонения, синхронизация `Id` в JSON, `NormalizeLuckCap` — не переехали.
Создание листа, помощник, быстрый НПС и библиотека `/npcs` (T2.4) — раздел «Создание и библиотека» ниже.

## Правила только в Core

Блоки зовут правила и не считают на месте (AUDIT, «Правила в разметке»): `DerivedAttributeRules` (максимумы, БкУ,
Комплекция, Скорость, Уклонение — **только для чтения**, в v1 их правили, и пересчёт молча затирал правку),
`SanityRules.Status`/`ApplyLoss`/`ResolveIntCheck`/…, `HabituationRules`, `MythosBookRules` (стадия руками —
`SetStage`, предпросмотр чтения — то же `Apply` на `CmJson.Clone` листа), `DevelopmentPhaseRules`, `WoundRules`,
`SheetSkillLayout` (раскладка, правки строк, база навыка из справочника — не 0), `SheetCopies` (копии оружия и
заклинаний), `CheckRules.Apply` (Удача и отметка из диалога проверки). Новое правило — в Core с тестом.

## Сохранение

- **Автосохранение — опрос слепка, а не подписка** (знание v1): поля правятся обычным `@bind` в блоках, слепок
  `CmJson.Serialize(лист)` раз в 3 с ловит любую правку разом. Разошёлся — `PUT …/sheet` с `If-Match` (версия
  `xmin`). Ручное «Сохранить» и тик делят один флаг занятости.
- **Конфликт** (409 `stale`, лист записали с другого устройства) — автосохранение **останавливается**, плашка
  «Лист изменили на другом устройстве»: «Перечитать» (правки отсюда пропадут) или «Записать мои поверх» (свежая
  версия, затем запись). Тост — один раз. Молчаливой перезаписи нет — так в v1 вкладки Хранителя и игрока
  затирали друг друга.
- **Отказ по смыслу** (400/403/404) тоже останавливает запись: повтор не поможет. Нет связи / 5xx — повтор на
  следующем тике, одно уведомление на серию ошибок, состояние — значок в шапке.
- **Черновик** — `localStorage` `cm.sheet-draft:{id}`: версия, на которой начата правка, и лист. Пишется **сразу**
  по событию `change` (всплывает от любого поля до `div.sheet`) — перезагрузка в 3-секундном окне правку не теряет;
  стирается после записи и при «Перечитать». При открытии: совпадает с базой — стирается молча (плашка только
  если расходится, знание v1); начат на той же версии — подставляется и уходит в базу сам; на старой версии —
  выбор «Восстановить мои» / «Отбросить».
- **Портрет и статус — колонки строки**, пишутся сразу и тоже с версией; перед этим уходит несохранённое в
  документе, иначе запись колонки сдвинула бы версию и следующий тик получил бы конфликт сам с собой.
- Игрок — из владельца строки (псевдоним в кампании или имя профиля), а не поле документа: в v1 «Сохранить»
  затирало его именем слота или «Unknown».

## Вёрстка (знание v1, iPad)

- **Секции** — одна карточка каждая; блоки внутри своих карточек не заводят, соседей разделяет линейка
  (`BodyClass="cm-stack"`). Окна блока — под **одним корнем** с ним: вторым корнем в `cm-stack` открытое окно
  получило бы рамку и отступ. Только для чтения — `fieldset disabled` в теле секции.
- **Меню секций** — липкая полоса над листом, ссылки `character/{id}#sheet-…` (с путём: голый `#…` при `<base href="/">`
  увёл бы на главную); на телефоне — короткие подписи.
- **«Личные данные»** — три колонки с `lg`, а не с `md` (на 768px «Состоянию» оставалось 240px, «Макс.» обрезало
  «11»); ниже `lg` столбик, характеристики и состояние — `max-w-md`. Подписи над полями (слева съедали 70px, имя
  ужималось до «Дж»). «Труд.» и «Чрез.» — текст. Шаг ПЗ/ПМ/Рассудка/Удачи — `cm-btn-sm cm-btn-icon` с `shrink-0`.
- **Отметки состояния** — группы (тело / рассудок), строка 40px; рядом встают по `@container` ширины блока, а не
  окна (на 1024px это самая узкая колонка). Отметки безумия здесь — мимо `SanityRules`, флаг приступа не трогают.
- **Навыки** — CSS columns: 1 → 2 (`sm`) → 3 (`xl`, а не `lg`: на портрете iPad «Антропология» наезжала на
  галочку). Строка плотная: крестик и галочка — `cm-tap-target`, касание имени расширено невидимым `::after`;
  своей кнопки проверки в строке нет. Строки — `@key`. Специализации на базе свёрнуты под родителем
  («Стрельба — ещё 6»), поиск их раскрывает.
- **Оружие** — одна разметка: строка-сетка; с `lg` — колонки под общей шапкой (подписи ячеек скрыты для глаз, не
  для диктора), ниже — ячейки с подписью, навык во всю ширину. Патроны и Неиспр. — колонки (в бою смотрят каждый
  раунд). Неразобранный урон — `UnparsedMark` (бой его не бросит).
- Портрет — рамка-`<label>` скрытого `InputFile` с обязательной подписью «Загрузить»/«Заменить» (наведения нет).
- Записи-`record` листа (заклинание, предмет) равны по значению: множества открытых строк — по ссылке
  (`ReferenceEqualityComparer`), `@key` на них не ставить (два одинаковых — дубль ключа).

## Рассудок, приступ, книги, фаза (знание v1)

- Два окна потерь: «последняя причина» (≥5 → подсказка проверки ИНТ с двумя кнопками исхода — бросает игрок) и
  «за день» (≥⅕ Рассудка на начало дня → бессрочное). Одно нажатие — одна причина. «Новый день» обнуляет оба.
- Приступ: режим VII/VIII, десять строк-кнопок (и после настоящей кости, и выбором Хранителя), длительность —
  бросить или вписать; текст приступа в лист не копируется. Строки 9–10 ведут к фобии/мании. Флаг «положен
  приступ» — только `SanityRules`; напоминание видно, пока сыщик безумен.
- Фобии и мании — только структурированные записи (табл. IX/X): текстовых граф «Фобии» и «Магические предметы»
  в 2.0 нет (решение владельца 2026-10-02).
- Книга Мифов — свой экземпляр чисел (правка не трогает справочник); чтение не применяется без числа потери
  (бросок здесь или вписанный); стадия руками — без эффектов.
- Фаза развития: набор отмеченных навыков — один раз на открытие; Мифы и Средства не отмечаются; отметки
  стираются только в окне («Стереть отметки и завершить» или «Снять отметки» с подтверждением на месте).
  **Любой бросок можно бросить или вписать** (правило проекта): d100 проверки опыта, Удачи и самолечения — `RollInput`,
  суммы NdM (прирост 1d10, +2d6 Рассудка за 90%, прирост Удачи 1d10 и Рассудка 1d6, кости Средств) — `DiceInput`. Окно
  кладёт вписанное в `EnteredDiceRoller` (невписанное — пустой слот, его бросит правило), считает только
  `DevelopmentPhaseRules`; кости каждого шага — его константы (`SkillGain`, `MasterySanity`, `CreditRatingDice`…).
- «Знакомые сыщики»: соседи — из `GET …/party` (живые имя, профессия, игрок); строка в документе появляется только
  с заметкой (со слепком имени), вписанные руками можно убрать.

## Проверки

Тап по имени навыка — справка (`SkillDetails`) с «Проверкой»; свой навык — сразу проверка; тап по СИЛ, ЛВК… и
«Удаче» — проверка характеристики; процент у оружия — проверка его навыка. Диалог — общий `Checks/SkillCheckModal`
с `Sheet`, `Catalog`, `InitialKey`; Удачу и отметку страница применяет `CheckRules.Apply`, в базу их уносит
автосохранение. Удача поднимает пройденную проверку на уровень выше; отметка за бросок, купленный Удачей, не
ставится, прежняя остаётся (решение владельца; правило — `Core/Checks`).

## Создание и библиотека (T2.4)

| Файл | Что |
|---|---|
| `Creation/CharacterCreatePage` | «Новый лист»: `/character/create/{campaignId}` (сыщик), `/character/create/npc` или `pregen?campaignId=&scenarioId=` (`template` старых ссылок — НПС). Способы: помощник, случайный, чистый лист (только по кнопке — ссылка ничего не пишет), у НПС — быстрый |
| `Creation/InvestigatorWizardPage` + `Wizard*Step` | помощник `/character/wizard?campaignId=&scenarioId=&kind=npc&random=1` (вид — `npc` или `pregen`) |
| `Creation/QuickNpcModal` | быстрый НПС; из сценария — с ролью и количеством (`Cast`) |
| `Creation/CreationLinks`, `CreationPlace`, `DerivedTiles`, `Stepper` | адреса и черновик, «куда ляжет», плитки производных, «− n +» |
| `Library/NpcLibraryPage`, `Library/CharacterSummaryCard` | `/npcs` (Хранитель): вкладки НПС/прегены и архив в адресе; карточка — одна и для сценария (T2.5a); «В сценарий» у НПС — `OnCast` → `Scenarios/CastNpcDialog` |

- **Всё считает Core** (`SheetBuilder`, `CreationPlan`, методы `InvestigatorDraft`, `QuickNpcRules`); страницы только
  показывают. Слоты профессии собирает `CreationPlan` страницы, шаги читают выбор по индексу слота (знание v1).
- **Любой бросок можно вписать**: характеристики, набор варианта 3, Удача — `DiceInput` (сумма костей, значение × 5 — правило
  Core), проверка ОБР — `RollInput` + `DiceInput` в `EnteredDiceRoller`, экстра-класс и списки биографии — `DiceInput` 1d10.
- **Место проверяется до первого шага** (`GET …/characters/new`): игрок не участник, у него уже активный сыщик в
  кампании, НПС чужой кампании — отказ с текстом сразу, а не на «Создать» (знание v1).
- Черновик помощника — `localStorage` `cm.investigator-draft:{вид}:{кампания|сценарий|library}`, пишется на каждую правку,
  стирается после создания и «Заново». `?random=1` бросает черновик и меняет адрес на тот же без `random` (`replace`):
  перезагрузка не перебрасывает. Эпоха — кампании или сценария (выбора эпохи в помощнике нет: современных данных нет).
- Шаги помощника: вперёд — только через проверку шага, назад и на уже пройденные — всегда (случайный сыщик открыт на
  «Итоге», любой шаг можно открыть и переиграть). «Итог» собирает лист тем же `SheetBuilder.FromDraft`, что и «Создать».
- Быстрый НПС из сценария пишет лист и связь одной записью — «лист есть, связи нет» не бывает, повтор не даёт двойника;
  отказ — окно остаётся открытым с текстом.
- Вёрстка: таблицы характеристик и навыков — `cm-table-wrap` (на телефоне листаются вбок, страница — нет); ячейка
  броска не уже `min-w-40`, иначе кнопка кости уезжала под поле; ряды кнопок — `flex-wrap`.
- **Специализации на базовом значении на листе свёрнуты под навыком-родителем — решение владельца (вопрос из #125).**
  Помощник, быстрый НПС и импорт строк для них не заводят, поэтому их листы выглядят так же.
