# Encounters (UI) — сцена: оболочка боя и погони

`/combat` и `/chase` (T2.6a) — одна оболочка `EncounterPage` на ядре Core (`Core/Encounters`, см. «Ядро сцены» и «Бой» в
[Core/CLAUDE.md](../../CampaignManager.Core/CLAUDE.md)) и API `IEncountersApi`
([Server/Encounters/CLAUDE.md](../../CampaignManager.Server/Encounters/CLAUDE.md)). Правила боя (T2.6b) — панель
`Combat/CombatPanel` в `ChildContent` страницы `/combat` (см. «Бой» ниже); погони (трасса, СКО, помехи, транспорт) — T2.6c,
так же — своей панелью с `EncounterSession` каскадом. Знание перенесено из `Combat/CLAUDE.md` и `Chase/CLAUDE.md` v1; обходы
v1 (`[PersistentState]`, снимки circuit, `RegisterPersistentService`, сохранение в `OnAfterRenderAsync`, `max-w-7xl`) — нет.

## Контракт: результат → предпросмотр → Apply

- Действие **не меняет участников**. Правило (Core) возвращает `EncounterResolution` (строки + эффекты), страница кладёт
  его в `state.Pending` (`EncounterEngine.Propose`) — предпросмотр виден и **переживает перезагрузку**. «Применить» —
  `EncounterEngine.Apply`, «Отменить» — `Cancel`. В v1 атака меняла участников до «Применить», а «Отменить» не возвращало
  патроны, ход, заклинивание и защиту цели (F-C02).
- **Третьего пути мимо Apply нет**: правка Хранителя руками (урон от падения, ПМ, «выбыл») — тоже эффект через
  предпросмотр (`EffectPanel`) или сразу `Apply(state, resolution)` (выбыл/вернуть). В v1 первая помощь, медицина, укрытие
  и полдюжины действий погони правили участников прямо в razor.
- Каждое действие страницы — `session.ChangeAsync(state => …)`: правка правилом Core, черновик вкладки, запись в базу
  **сразу**, затем — листы. Тик (3 с) повторяет то, что не прошло.

## Запись в лист

- `EncounterEngine.Apply` ставит эффекты участников с листом в `state.SheetWrites`, `EncounterSheetSync` пишет их через API
  листа (T2.3): прочитать свежий лист, применить `EncounterSheetEffects` (ПЗ — `WoundRules`, рассудок — `SanityRules`/
  привыкание, ПМ, МОЩ), записать с `If-Match`. **409 — перечитать и применить ещё раз**: эффект — приращение, поэтому
  правка игрока не теряется, а открытая у игрока вкладка листа получит свой 409 и плашку «перечитать» (T2.3).
- Листы пишутся, **только когда сцена в базе совпадает с вкладкой**: очередь живёт в документе, и запись в лист до
  сохранения сцены при перезагрузке легла бы второй раз. Оставшееся окно — «лист записан, ответ о сцене не дошёл» (один
  запрос): тогда при повторе эффект ляжет второй раз. Принято сознательно; виден в журнале («Записано в лист» дважды).
- Нет связи — запись остаётся с текстом ошибки и повторится сама; 403/404/400 — «заблокирована»: у строки участника
  «Повторить» / «Не записывать».
- Снимок участника после записи — **из записанного листа** (там привыкание и поправки книги); при открытии сцены снимки
  листов перечитываются (лист мог поправить игрок).

## Состояние вкладки

- Открытая сцена — в адресе (`?id=`); `/combat` без него открывает единственную идущую или показывает «Новая сцена» и
  «Идут сейчас». `?campaign=` — продолжить сцену этой кампании или начать в ней.
- Черновик `cm.encounter-draft:{id}` (версия + документ) пишется до записи и стирается после. При открытии: совпадает —
  стираем молча; начат на той же версии — просто не дошёл, уходит сам; на старой — «Восстановить мои / Отбросить».
- Конфликт (409 `stale`, сцену записала другая вкладка) останавливает запись: «Перечитать» или «Записать мои поверх».

## Знание v1, которое здесь живёт

- **Id участника ≠ id листа**; лист в сцене — один раз (строка в выборе гаснет «уже в сцене», ядро отсекает повтор);
  тварей — сколько угодно за раз, с номерами «#1», «#2» (`EncounterEngine.Add`).
- **Сторона** — сыщик с сыщиками, тварь — противник, НПС — нейтрален или по роли в сценарии
  (`EncounterParticipants.SideOf`: союзник — с сыщиками, враг — против). Хранитель меняет сторону в строке. Шальная пуля
  (T2.6b) ищет союзника по стороне.
- **Очередь** — по ЛВК (стр. 110), инициатива твари 0 — по ЛВК; ход — по id, удаление и выбывание его не сдвигают;
  отложенный ход — только этот раунд. Удачи и рассудка у тварей нет — полос нет.
- **Привыкание** (стр. 167) — по виду и имени, а не по особи: источник потери в `EffectPanel` — тварь сцены, вид —
  `SourceName` без номера; сто глубоководных отнимают столько же, сколько один. Крах проверки рассудка — максимум
  провальной части (кнопка «Крах»).
- **Журнал** — на всю ширину под рабочей областью (длинная запись в колонке портрета iPad разворачивалась на десяток
  строк), свежее сверху, цвет — по категории (движение, препятствие, насилие, рассудок), а не по виду.
- Оформление: только палитра дизайн-системы, иконки Font Awesome, классы литералами; строка участника — строка в
  карточке, не карточка; смысл не держится на `title`.

## Вёрстка (iPad)

- Рабочая область — 5/7 колонок с `lg` (участники / результат и панели), ниже — столбик; полосы встают рядом по
  `@container` ширины строки (на 1024px колонка участников самая узкая).
- Шапка — только музыка сцены (`MusicPoolButton`, тег «бой»/«погоня»); «Участник» — у списка, «Завершить» — у раунда: на
  телефоне шапка вмещает две подписанные кнопки, третья уезжала за край.
- Ряды кнопок — `flex-wrap`, кнопки — `cm-btn-sm` с подписью. Проверено на 1366×1024, 1024×1366 и 390×844.

## Стыки

- **Состав сценария (T2.5a)** — `ScenarioCastSource` над `IScenariosApi.GetAsync`: НПС — лист, сторона по роли; твари —
  итоговый статблок сценария (`ScenarioCreatureDto.Statblock`), количество — из состава. Сценарий выбирают в окне; когда
  будут прохождения (T2.5c), можно подставлять сценарий прохождения кампании сцены.
- **Статисты**: НПС состава с количеством больше одного — снимки листа **без ссылки** на него («#1, #2», заметка
  «статист»): урон троих громил в один общий лист не пишется, а «один лист — один участник» в ядре и на сервере
  соблюдается. Один — обычная ссылка, его эффекты пишутся в лист.
- **T2.6b/c** — панели в `ChildContent` (`[CascadingParameter] EncounterSession`), их резолв — `EncounterResolution`, их
  новые эффекты и записи журнала — члены `EncounterEffectKind`/`EncounterLogKind` (ветки в `EncounterEngine`,
  `EncounterSheetEffects`, строки в `EncounterText`). Кости в бою — `Checks/SkillCheckPanel` с `InCombat`.

## Бой (T2.6b)

- **Панель правил не считает.** Каждая вкладка собирает настройку и зовёт `CombatRules` (Core) — результат идёт на тот же
  предпросмотр оболочки (`Propose`), меняет участников только «Применить». Без предпросмотра — только расстановка
  («Огнестрел наготове», «Подняться», необязательные правила, броски инициативы).
- **`CombatPanelBase`**: каскад `EncounterSession` зафиксирован, у панелей нет параметров — поэтому они **подписаны на
  `EncounterSession.Changed`** (новый ход, применённый результат). Без подписки «кто действует» не шёл за ходом. Действующий
  по умолчанию — тот, чей ход (знание v1); цель — первый живой с другой стороны; лечит — первый в сознании с лучшей Первой
  помощью (у умирающего, чей ход, бинтовать некому).
- **«Броски со стола»** — свёрнутый `<details class="encounter-rolls">`: d100 — `RollInput` (с костями, которые насчитала
  таблица `AttackModifiers`, и сложностью дальности), суммы — `EnteredNumber`/`DiceInput`. Не вписано — бросит правило. ВЫН
  цели при серьёзной ране вписывается (в v1 нельзя было, F-C05).
- **Проверки ВЫН умирающих** — плашка над вкладками (`CombatRules.DyingChecksDue`): первая — в конце **следующего** раунда
  после «при смерти», дальше каждый раунд; стабилизированные — во вкладке «Раны», раз в час. Нажатие «Проверка ВЫН» — тоже
  предпросмотр.
- **Строка участника** показывает «мёртв», «при смерти, стабилизирован» и отметки боя словами (лежит, схвачен, целится,
  укрылся, без атаки в раунде N, оружие заклинило, творит «…»). Мёртвый ход не получает (`EncounterQueue`).
- **Заклинание**: цена по книге — подсказка `SpellStatsReader` (число — сразу в поле, кости — кнопкой «бросить»), Хранитель
  подтверждает числа; 2+ раунда — долгое сотворение, его «Сработало» / «Бросить сотворение» во вкладке; эффект на цель —
  «Эффект Хранителя». Первое сотворение — только у сыщика (НПС и твари проверку не проходят, знание v1).
- **Рассудок**: источник — тварь сцены (её «успех/провал» подставляется, вид — для привыкания). Исход ИНТ едет в лист;
  привыкание, пороги ⅕ и приступ решает лист (`EncounterSheetEffects`).
- **Кости** — общий `Checks/SkillCheckPanel` с `InCombat` (повторов нет, стр. 102).
- Имя компонента `CombatSanityPanel`, а не `SanityPanel`: у листа (`Characters/SanityPanel`) есть свой, и разметка
  `<SanityPanel />` без префикса бралась из листа — страница падала в `ErrorBoundary`. Новый компонент здесь — проверяй имя.
- Вёрстка: семь вкладок в колонке 7/12 переносятся на вторую строку (на 1024px портрета колонка ~400px); вбок ничего не
  уезжает и на 390px. Проверено на 1366×1024, 1024×1366 и 390×844 (`scrollWidth` по всем вкладкам с раскрытыми бросками).
