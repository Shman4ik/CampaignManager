# Admin (UI) — пользователи, заявки, файлы

Страницы админки, все — `[Authorize(Policy = Policies.Admin)]` (не `Roles`: в куке сервера роли нет). Данные —
`IAdminApi` и `IFilesApi`; правила — [Server/Admin/CLAUDE.md](../../CampaignManager.Server/Admin/CLAUDE.md).
Знание перенесено из `Features/Admin` v1.

| Адрес | Файл | Что |
|---|---|---|
| `/admin/users` | `AdminUsersPage` | все пользователи: поиск по имени и почте, фильтр по роли, смена роли |
| `/admin/applications` | `AdminApplicationsPage` | заявки на Хранителя: вкладки по статусу (`?status=pending\|approved\|rejected\|all`), одобрить, отклонить с комментарием |
| `/admin/files` | `AdminFilesPage` | файлы-сироты: отчёт, удаление отдельной кнопкой (перенесено с `/dev/files`, T1.5) |

- **Пункты меню** — три строки `NavMenu` в группе «Система» (`NavAudience.Admin`). Счётчик заявок у «Заявок» —
  `AdminBadges` (синглтон): наполняет `MainLayout` один раз при входе администратора (`GET /api/v1/admin/summary`),
  обновляет страница заявок после одобрения и отказа. Тот же счётчик — на вкладке «Ожидают» и на кнопке «Заявки» в
  шапке пользователей. Адреса — `AdminPages`.
- **Список пользователей грузится целиком** (людей десятки), поиск, фильтр и страницы — на клиенте, любой фильтр
  сбрасывает страницу на первую.
- **Смена роли — `<select>` в строке, с подтверждением** (`DialogService`): на iPad промахнуться по списку легко, а
  роль администратора — не то, что меняют случайно. Отмена или отказ сервера (последний администратор — 409)
  возвращают прежнее значение: у `select` ключ с «поколением», которое растёт при отмене, — иначе DOM показал бы
  выбранное, а разметка его не поменяла. `value` у `<option>` — имя члена `UserRole`. Снял роль с себя — меню
  перечитывает сессию (`IUserSession`), админка из него пропадает сразу.
- **Одобрить** — зелёная `Success` (одобрение чужой заявки), без подтверждения: роль можно вернуть на странице
  пользователей. **Отклонить** — `OutlineError`, окно с необязательным комментарием (его увидит игрок) и красной
  `Error`-кнопкой. У заявки виден бейдж текущей роли подавшего — одобренная заявка игрока, который всё ещё игрок,
  бросается в глаза (так выглядит след ошибки v1 на перенесённых данных).
- Бейджи — `Tone` по смыслу (`RoleLabels`): статус «ожидает» — warning, «одобрена» — success, «отклонена» — error;
  роль — графит/зелёный/сталь, как в кабинете.
- Время — `LocalTime.DateTime` (пояс браузера); последний вход у ни разу не входившего в 2.0 — «не входил».
- Сироты: сначала «Найти сирот», удаление — только файлов из отчёта и после `ConfirmDeleteAsync`; результат —
  `Alert` (удалено, пропущено, объекты, которые хранилище не удалило). Таблица — `DataTable` с карточками на телефоне.

Проверка — 1366×1024 и 1024×1366 под `/dev/login?as=admin`. Действия с ролями и заявками на ветке Neon `dev` —
только над `dev-*@cm.test`: там же лежат настоящие пользователи и их заявки.
