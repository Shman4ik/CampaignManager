# Checks — диалог проверки

Проверка навыка или характеристики по главе 5 (стр. 80–97) — **один диалог на всё приложение**:
сложность, бонусные и штрафные кости, бросок автоматом или с настоящих костей, трата Удачи, повторная
проверка, отметка для фазы развития; плюс групповая проверка восприятия. Знание перенесено из
`CampaignManager.Web/Components/Features/Checks/CLAUDE.md` v1 (T2.7); обходы v1 (circuit, разбор имени
цели строкой, `IsUsed` по имени навыка) — нет.

## Где что

| Что | Где |
|---|---|
| Правила: что разрешено после броска, Удача, отметка, `Apply` | `Core/Checks/CheckRules` |
| Цели с листа (характеристики, Удача, навыки по группам), ключи | `Core/Checks/CheckSubjects`, `CheckSubject` |
| Лучший в групповой проверке, навыки восприятия | `Core/Checks/GroupCheck` |
| Уровень успеха, пороги | только `Core/Dice/Check` |
| Цена Удачи | только `Core/Characters/LuckRules` |
| Панель, окно, групповая, пикеры | `UI/Checks/*` |
| Живой пример на тестовом листе | `/dev/checks` (только Development) |

## Компоненты

- `SkillCheckPanel` — сама проверка, без карточки (место — тело окна или `cm-card`). Режимы:
  - **лист** — `Sheet` + `Catalog`: цель — выпадающий список с листа (характеристики, Удача, навыки по
    группам бланка; навык справочника, которого на листе нет, — по базе); при `InitialKey` он за ссылкой «Другой навык»
    (`check-change-target`), без цели — виден сразу. С `OnSheetChange` появляются кнопки Удачи и отметки;
  - **состав** — `Party` (`CheckInvestigator`: id, имя, игрок, лист) + `Catalog`: выбор сыщика, листы
    только читаются, Удача и отметка — подсказкой «на листе сыщика»;
  - **вручную** — ни листа, ни состава: подпись и значение вписывает Хранитель.
  - `InitialKey` — ключ цели (`skill:{id}`, `char:STR`, `luck`). Ключ навыка — id справочника, поэтому
    один и тот же ключ работает на листе любого сыщика (проверка локации T2.5: `scenario_checks` →
    `CheckSubjects.KeyFor`/`Resolve`). Разбор имени «СИЛ»/«Сила»/«Стрельба (П)» из v1 не переносится —
    ссылку разрешил перенос T1.3.
  - `InitialInvestigatorId` + `OnInvestigatorChanged` — сыщик, выбранный в прошлой проверке: родитель (режим игры
    сценария) держит его в состоянии страницы и передаёт при следующем открытии; нет в `Party` — игнорируется.
  - `Details` — `RenderFragment<bool>` (параметр — проверка пройдена, с учётом Удачи и повтора) **сразу под результатом
    броска**, выше Удачи и повтора (`data-testid="check-details"`); до броска не рисуется. Режим игры кладёт туда
    исход сценария: выпавший — цветным блоком первым, второй свёрнут `<details>`. Порядок и высота — правило из
    повторного аудита R3: самое важное для Хранителя не уходит за край окна.
  - `InCombat` — кости в бою: повторов нет (стр. 102).
  - `OnResolution` (`CheckResolution`: ключ цели и `Passed`) — итог изменился (бросок, повторный бросок, Удача, «Новая проверка» —
    тогда `Passed = null`). Нужен листу: проверку ИНТ из тревоги Рассудка он закрывает сам, когда окно закрыли
    (`SheetContext.IntCheckPending`, `CharacterPage.CheckOpenChanged`). Остальным — не обязателен.
- `SkillCheckModal` — панель в общем `Modal` (Medium, `class="cm-modal-top"`: окно у верхнего края растёт вниз на броске, исходе и
  Удаче, поля не сдвигаются; выше экрана тело прокручивается. Прежние Large и `MinHeight="60rem"` оставляли на 834×1056 пустую
  нижнюю половину окна — владелец, 2026-10-03; строка цели над сложностью занимает место, пока цель не выбрана). Панель пересоздаётся на каждое открытие (`@key`).
- `DifficultyPicker`, `ExtraDicePicker` — сложность (`Segmented`: три сегмента, «≤ N» при известном значении; выбранный светлым
  с галочкой, не главной кнопкой) и итог
  костей −2…+2 одним числом (одна бонусная гасит одну штрафную, стр. 89).
- `GroupCheckPanel` — групповая проверка восприятия (гл. 10, стр. 200–201): навык (быстрые кнопки
  Внимание/Слух/Психология по коду), сложность, «Бросить за всех» и поле броска у каждого. С `Party` +
  `Catalog` значения берутся с листов; без них сыщиков вписывают руками (имя и значение). Состояние —
  `GroupCheckDraft` снаружи (ширма держит один на вкладку), иначе своё.

## Порядок в окне (g2 7.1, решение оркестратора)

Окно — окно посреди игры, главное в нём — бросок, и он **над сгибом** на всех трёх вьюпортах (1194×696: тело 462px видимых;
раньше «Бросок» стоял вторым экраном, а на телефоне не был виден вовсе). Сверху вниз:

1. «Кто проверяется» (только режим состава);
2. цель крупно: «Внимание 63%» и справа «Другой навык» — полный список из 90 вариантов раскрывается по ссылке (раньше стоял
   вторым блоком и троил число: «Внимание 63%», «Внимание (63)», «Обычная ≤ 63»); без цели список виден сразу;
3. «Сложность» и «Бонусные и штрафные кости» (рядом, если влезают);
4. **«Бросок»**; после него условия **убираются** (они заперты, а итог уже называет сложность «Нужно ≤ 63 (обычная сложность)»),
   чтобы Удача и повтор — то, что делают дальше, — не уходили за край окна; бонусные и штрафные кости остаются строкой;
5. итог, `Details` сценария, Удача, повтор, отметка. **Невозможное не рисуется** (правило 8, g4 13.11): «Потратить Удачу» — только
   если есть что купить (не на проверку Удачи, не крах, дотянуть можно), «Повторная проверка» — только если повторять можно (не бой,
   не Удача, не Ближний бой и Стрельба, не крах); объяснение «нельзя» ничего не даёт игроку;
6. **«Справка по навыку»** — последним блоком: открытая, она занимала экран-два и уносила бросок с результатом.

Из режима игры сценария (`Party`, `InitialName`; g4 13.9–13.12): цель, пришедшая из сценария, названа крупной строкой — поля «Что
проверяем» нет, вписывают только значение; единственный сыщик партии выбран сразу, и значение его навыка подставлено; «Без
дополнительных костей» не пишется (умолчание). После броска (и повторного) фокус уходит на итог (`tabindex="-1"`, `FocusAsync`), и тело окна прокручивается к нему — без
JS-модуля. Блок «Отметка для фазы развития» **не рисуется**, когда отмечать нечего: характеристике, Удаче, Мифам и Средствам
отметку не ставят никогда (раньше — абзац про то, чего на экране нет); у навыка с причиной («с бонусной костью», «куплен Удачей»)
причина остаётся. Кнопка — «Отметить: Внимание», имя без кавычек. Причины из `CheckRules` (`LuckBlockReason`, `PushBlockReason`,
`MarkBlockReason`) **без номеров страниц** (правило 10: «в результате проверки номеров нет»).

## Диалог сам лист не пишет

Трата Удачи и отметка развития уходят родителю событием `OnSheetChange(CheckSheetChange)`; родитель (лист
T2.3) применяет их `CheckRules.Apply(sheet, catalog, change)` и сохраняет **своим** путём (запись с
`If-Match`). Своего пути записи у диалога нет и заводить его нельзя: открытый лист затёр бы такую запись
своим следующим сохранением (урок v1). Навык справочника, которого на листе нет, получает строку с базой.

**Удача и отметка за этот бросок** (решение владельца 2026-10-02): купленный Удачей успех отметки не даёт —
но только за этот бросок. Панель помнит, ставила ли она отметку сама (`_marked`); трату собирает
`CheckRules.LuckSpend(subject, cost, markedThisRoll)`, и если отметка была своя — она уходит в
`UndoMarkOfThisRoll` и снимается вместе со списанием Удачи. Отметку, стоявшую на листе до броска
(«уже стоит»), трата не трогает. После траты кнопки отметки нет — «Успех куплен Удачей».

## Правила, где легко ошибиться

- **Крах зависит от сложности** (стр. 88): 96–100 — крах, если нужно выбросить меньше 50; у трудной
  проверки навыка 55 — уже на 96. Поэтому `LuckBlockReason` проверяет крах по итогу `Check.Evaluate` со
  сложностью, а не через `LuckRules.CanSpendOn` (та видит обычную сложность).
- **Критический успех Удачей не покупается** (стр. 97): уровень с порогом 01 не предлагается (при навыке
  5–9 нет «чрезвычайного», 2–3 — «трудного»). В v1 вариант был (F-S03, исправлено в T2.7).
- **Повторяют только навыки и характеристики** (стр. 83): не Удачу, не Рассудок, не в бою и не Ближний
  бой/Стрельбу (стр. 102), не после краха (стр. 87) и один раз. Огнестрел — **по коду** (`skill.firearms`
  и его специализации, `skill.fighting.*`), а не по имени: в v1 «Автомат» проходил (F-C09). На повтор Удачу
  не тратят — либо повтор, либо Удача (стр. 97).
- **Осечка** (стр. 97, 117): окно, открытое касанием оружия в «Игре» (`SheetContext.CheckWeapon`), получает порог
  (`Malfunction`); бросок не ниже — итог «Осечка (96–100): оружие не выстрелило», Удачи нет, отметки нет
  (`CheckRules.IsMalfunction`, `LuckBlockReason(…, malfunction)`, `MarkBlockReason(…, malfunction)`). Порог относится только к
  цели `InitialKey`: «Другой навык» — без осечки.
- **Отметка развития** (стр. 92, 97): только навыку, не Мифам и не Средствам (по коду,
  `DevelopmentPhaseRules.CanBeChecked`), не с бонусной костью и не за успех, купленный Удачей. Успех
  повторной проверки отметку даёт. Ставится только кнопкой после успеха.
- **Пройденную проверку Удачей поднимают** до уровня выше (стр. 97): блок «Поднять уровень Удачей» — только
  у листа с обработчиком и только если есть до чего поднимать (у критического и чрезвычайного его нет). Под
  кнопками — предупреждение, что отметка за этот бросок снимется, если её уже поставили.
- **После первого броска условия (цель, сложность, кости) заблокированы** до «Новая проверка»: иначе на
  экране остался бы итог броска против другого значения.
- **Любой бросок можно вписать** — `RollInput`. С бонусной костью Хранитель вписывает меньший из вариантов
  десятков, со штрафной — больший (подсказка под полем).
- Рассудка среди целей нет намеренно — у его проверки свои правила (без костей, Удачи и повтора) и своя
  панель листа.

## Групповая проверка

Лучший — прошедший с наивысшим уровнем успеха, при равенстве — с большим значением навыка, полное
равенство — все такие (`GroupCheck.Best`, в v1 жило в разметке). Строки **не** пересортировываются по
результату: Хранитель вписывает броски по порядку, и строка не должна уезжать из-под пальца. Отметки игроки
ставят у себя. В ширме групповая проверка пока в ручном режиме: состав кампании подключится, когда будут
API кампаний и листов — **подключено в T2.3** (`KeeperScreen/KeeperGroupCheck`: выбор кампании Хранителя).

## Где появится в интерфейсе

- Лист сыщика (T2.3, **подключён**): тап по имени навыка (справка → «Проверка»), по сокращению характеристики,
  «Удаче» или проценту оружия → `SkillCheckModal` с `Sheet`, `Catalog`, `InitialKey` и `OnSheetChange`; страница
  применяет `CheckRules.Apply`, в базу уносит автосохранение листа. Отдельного кубика в строке навыка нет.
- Режим игры сценария (T2.5b, **подключён**): «Проверить» у проверки локации → `Party` (сыщики кампании выбранного
  прохождения), `InitialKey` из `scenario_checks` (`CheckSubjects.KeyFor`), сложность проверки (`Scenarios/ScenarioPlay`).
- Бой (T2.6): кости в бою — `SkillCheckPanel` с `InCombat`.
- Ширма Хранителя — групповая проверка (`KeeperScreen/CLAUDE.md`).

## Вёрстка

- Сложность и кости — друг под другом: рядом в окне кнопки «Чрезвычайная ≤ 11» переносились бы.
- Кнопки — `Button Small` (36px) с подписью; цвет — смысл (`Primary` у выбранного варианта).
- Выпавшее число — крупно (`.check-roll`), уровень — `Badge` с тоном `LevelText` (общий с `RollInput`).
- Проверено на 1194×696, 834×1056 и 393×651 (2026-10-03, F2a): начальное состояние и самое высокое (провал с Удачей и
  повтором) — всё, кроме справки, помещается без прокрутки на двух первых и почти на телефоне (тело 474px, прокрутка 22px).
