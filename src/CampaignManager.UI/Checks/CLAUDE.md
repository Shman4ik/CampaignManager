# Checks — диалог проверки

Проверка навыка или характеристики по главе 5 (стр. 80–97) — **один диалог на всё приложение**:
сложность, бонусные и штрафные кости, бросок автоматом или с настоящих костей, трата Удачи, повторная
проверка, отметка для фазы развития; плюс групповая проверка восприятия. Знание перенесено из
`CampaignManager.Web/Components/Features/Checks/CLAUDE.md` v1 (T2.7); обходы v1 (circuit, разбор имени
цели строкой, `IsUsed` по имени навыка) — нет.

## Где что

| Что | Где |
|---|---|
| Правила: что разрешено после броска, Удача, отметка, `Apply` | `Core/Checks/CheckRules` |
| Цели с листа (характеристики, Удача, навыки по группам), ключи | `Core/Checks/CheckSubjects`, `CheckSubject` |
| Лучший в групповой проверке, навыки восприятия | `Core/Checks/GroupCheck` |
| Уровень успеха, пороги | только `Core/Dice/Check` |
| Цена Удачи | только `Core/Characters/LuckRules` |
| Панель, окно, групповая, пикеры | `UI/Checks/*` |
| Живой пример на тестовом листе | `/dev/checks` (только Development) |

## Компоненты

- `SkillCheckPanel` — сама проверка, без карточки (место — тело окна или `cm-card`). Режимы:
  - **лист** — `Sheet` + `Catalog`: цель — выпадающий список с листа (характеристики, Удача, навыки по
    группам бланка; навык справочника, которого на листе нет, — по базе). С `OnSheetChange` появляются
    кнопки Удачи и отметки;
  - **состав** — `Party` (`CheckInvestigator`: id, имя, игрок, лист) + `Catalog`: выбор сыщика, листы
    только читаются, Удача и отметка — подсказкой «на листе сыщика»;
  - **вручную** — ни листа, ни состава: подпись и значение вписывает Хранитель.
  - `InitialKey` — ключ цели (`skill:{id}`, `char:STR`, `luck`). Ключ навыка — id справочника, поэтому
    один и тот же ключ работает на листе любого сыщика (проверка локации T2.5: `scenario_checks` →
    `CheckSubjects.KeyFor`/`Resolve`). Разбор имени «СИЛ»/«Сила»/«Стрельба (П)» из v1 не переносится —
    ссылку разрешил перенос T1.3.
  - `InCombat` — кости в бою: повторов нет (стр. 102).
- `SkillCheckModal` — панель в общем `Modal` (Large). Панель пересоздаётся на каждое открытие (`@key`).
- `DifficultyPicker`, `ExtraDicePicker` — сложность (три кнопки, «≤ N» при известном значении) и итог
  костей −2…+2 одним числом (одна бонусная гасит одну штрафную, стр. 89).
- `GroupCheckPanel` — групповая проверка восприятия (гл. 10, стр. 200–201): навык (быстрые кнопки
  Внимание/Слух/Психология по коду), сложность, «Бросить за всех» и поле броска у каждого. С `Party` +
  `Catalog` значения берутся с листов; без них сыщиков вписывают руками (имя и значение). Состояние —
  `GroupCheckDraft` снаружи (ширма держит один на вкладку), иначе своё.

## Диалог сам лист не пишет

Трата Удачи и отметка развития уходят родителю событием `OnSheetChange(CheckSheetChange)`; родитель (лист
T2.3) применяет их `CheckRules.Apply(sheet, catalog, change)` и сохраняет **своим** путём (запись с
`If-Match`). Своего пути записи у диалога нет и заводить его нельзя: открытый лист затёр бы такую запись
своим следующим сохранением (урок v1). `Apply` списывает Удачу через `LuckRules.Spend` **без навыка** —
отметку за эту проверку диалог ещё не ставил (её дают только после успеха и не за купленный), а стоящая —
от прошлого честного успеха; навык справочника, которого на листе нет, получает строку с базой.

## Правила, где легко ошибиться

- **Крах зависит от сложности** (стр. 88): 96–100 — крах, если нужно выбросить меньше 50; у трудной
  проверки навыка 55 — уже на 96. Поэтому `LuckBlockReason` проверяет крах по итогу `Check.Evaluate` со
  сложностью, а не через `LuckRules.CanSpendOn` (та видит обычную сложность).
- **Критический успех Удачей не покупается** (стр. 97): уровень с порогом 01 не предлагается (при навыке
  5–9 нет «чрезвычайного», 2–3 — «трудного»). В v1 вариант был (F-S03, исправлено в T2.7).
- **Повторяют только навыки и характеристики** (стр. 83): не Удачу, не Рассудок, не в бою и не Ближний
  бой/Стрельбу (стр. 102), не после краха (стр. 87) и один раз. Огнестрел — **по коду** (`skill.firearms`
  и его специализации, `skill.fighting.*`), а не по имени: в v1 «Автомат» проходил (F-C09). На повтор Удачу
  не тратят — либо повтор, либо Удача (стр. 97).
- **Отметка развития** (стр. 92, 97): только навыку, не Мифам и не Средствам (по коду,
  `DevelopmentPhaseRules.CanBeChecked`), не с бонусной костью и не за успех, купленный Удачей. Успех
  повторной проверки отметку даёт. Ставится только кнопкой после успеха.
- **После первого броска условия (цель, сложность, кости) заблокированы** до «Новая проверка»: иначе на
  экране остался бы итог броска против другого значения.
- **Любой бросок можно вписать** — `RollInput`. С бонусной костью Хранитель вписывает меньший из вариантов
  десятков, со штрафной — больший (подсказка под полем).
- Рассудка среди целей нет намеренно — у его проверки свои правила (без костей, Удачи и повтора) и своя
  панель листа.

## Групповая проверка

Лучший — прошедший с наивысшим уровнем успеха, при равенстве — с большим значением навыка, полное
равенство — все такие (`GroupCheck.Best`, в v1 жило в разметке). Строки **не** пересортировываются по
результату: Хранитель вписывает броски по порядку, и строка не должна уезжать из-под пальца. Отметки игроки
ставят у себя. В ширме групповая проверка пока в ручном режиме: состав кампании подключится, когда будут
API кампаний и листов (T2.2/T2.3) — страница передаст `Party` + `Catalog`.

## Где появится в интерфейсе

- Лист сыщика (T2.3): тап по имени навыка или по сокращению характеристики → `SkillCheckModal` с
  `Sheet`, `Catalog`, `InitialKey` и `OnSheetChange`. Отдельного кубика в строке навыка нет — строки
  держим плотными.
- Режим игры сценария (T2.5b): «Проверить» у проверки локации → `Party` (сыщики кампании прохождения),
  `InitialKey` из `scenario_checks`, сложность локации.
- Бой (T2.6): кости в бою — `SkillCheckPanel` с `InCombat`.
- Ширма Хранителя — групповая проверка (`KeeperScreen/CLAUDE.md`).

## Вёрстка

- Сложность и кости — друг под другом: рядом в окне кнопки «Чрезвычайная ≤ 11» переносились бы.
- Кнопки — `Button Small` (36px) с подписью; цвет — смысл (`Primary` у выбранного варианта).
- Выпавшее число — крупно (`.check-roll`), уровень — `Badge` с тоном `LevelText` (общий с `RollInput`).
- Проверено на 1366×1024, 1024×1366 и 390×844 (диалог видит игрок).
