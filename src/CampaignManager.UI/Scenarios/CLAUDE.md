# Scenarios (UI) — библиотека и рабочее место сценария

Страницы T2.5a. Данные — только `IScenariosApi` (`Contracts/Scenarios`), справочники `ICatalogApi<T>` и библиотека листов
`ICharactersApi`; права решает сервер ([Server/Scenarios/CLAUDE.md](../../CampaignManager.Server/Scenarios/CLAUDE.md)),
UI прячет кнопки по `CanEdit`/`CanDelete`. Знание перенесено из `Features/Scenarios/CLAUDE.md` v1; обходы v1 (режим и
локация в адресе «чтобы пережить паузу circuit», снимок пререндера, модалки на `@ref` + `Show()` со своим
`StateHasChanged`, глубокое копирование локации) — нет.

## Страницы

| Адрес | Файл | Что |
|---|---|---|
| `/scenarios` | `ScenariosPage` | библиотека: поиск, карточки (три колонки только с `xl`), «Новый сценарий», «Удалить» автору |
| `/scenarios/new` | `ScenariosPage` | та же страница с открытой формой нового сценария (адрес v1) |
| `/scenarios/{id}` | `ScenarioPage` | рабочее место, вкладка — `?tab=` (`ScenarioLinks.Tabs`) |
| `/scenarios/{id}/edit` | `ScenarioPage` | адрес правки v1: «Описание» с открытой формой шапки (форма — **после** загрузки) |

Режим игры — `?mode=play&location=&handout=` того же адреса (T2.5b, `ScenarioLinks.Play`); второй экран
`/scenarios/{id}/handouts/{handoutId}` — статическая страница сервера (T2.5b). Рабочее место эти параметры не трогает.

## Рабочее место

- **Одна страница с вкладками вместо пары «просмотр + правка»** v1 (1 823 строки; описание и журнал рисовались дважды).
  Вкладки: Описание, Текст, Локации, Проверки, Факты, Раздатки, Твари, Предметы, НПС, Прегены — по компоненту
  `Scenario*Tab` на каждую. На 1366 вкладки встают в две строки (`cm-tabs` переносится).
- **Читается одним запросом, пишется по строке.** Вкладка зовёт свой адрес API и просит страницу перечитать сценарий
  (`OnChanged` → `AsyncContent.ReloadAsync`, данные на экране не прячутся): копии сценария во вкладках нет, правка
  соседней вкладки (и другого устройства) приходит с перечитыванием.
- Общее у вкладок — `ScenarioTabBase`: удаление с подтверждением (`«Убрать»` — связь, без «нельзя отменить»), порядок,
  тосты. Кнопки строки — `PartRowActions`: «Изменить»/«Удалить», а в режиме «Порядок» — «Выше»/«Ниже» (четыре подписанные
  кнопки в строке на портрете не помещались, голые стрелки на касание не объясняют; перетаскивания пальцем в длинном
  списке нет).
- **Модалки декларативные** (`Open`), форма заполняется при открытии (`Open && !_wasOpen`), ошибка — Alert в окне, окно
  не закрывается, кнопки выключены на время записи (v1: второй тап заводил раздатку дважды). Закрывает вкладка.
- **Шапка и текст — с версией.** «Изменили на другом устройстве» — Alert с «Перечитать». Текст Хранителя длинный: пока
  не записан, он в `localStorage` `cm.scenario-text:{id}` (по событию `change`), при открытии вкладки недописанный текст
  возвращается в редактор; «Перечитать» после конфликта оставляет в поле свой текст и берёт свежую версию.
- **Локации** — дерево с отступом (`pl-4`/`pl-10`/`pl-16`/`pl-22` — **классами**: `style="padding-left: @(1.5)rem"` в
  WebAssembly с культурой `ru-RU` даёт «1,5rem», и браузер выбрасывает правило). Касание строки раскрывает описание
  (Markdown) и проверки; там же «Вложенная локация». Родителем в форме нельзя выбрать саму локацию и её потомков.
- **Проверки** — группами по локациям (путь «Дом › Подвал»), «Сюда» у группы; форма — навык из справочника (весь, с
  родителями специализаций), характеристика или Удача, сложность кнопками `DifficultyPicker` (стр. 80), тексты успеха и
  провала. Метка вида — только у характеристики (у Удачи цель и вид совпадают).
- **Факты** — строки с видом-меткой, содержание раскрывается (Markdown).
- **Раздатки** — миниатюра, название (пометка Хранителя), начало текста игрокам и отдельной строкой «Хранителю: …».
  Картинка — `Catalogs/ImagePicker` (только изображения).
- **Твари** — из бестиария через `CatalogPickerModal` (сколько, где, заметки), раскрытие — заметки (Markdown: их пишут
  с разметкой) и итоговый статблок `StatblockView`; «свой статблок» — метка, в правке — «Идти за бестиарием».
- **Предметы** — «Из справочника» (выбор) или «Свой реквизит» (форма); описание и заметки — Markdown.
- **НПС** — `CharacterSummaryCard` с `Framed="false"` строками одной карточки (`cm-stack`); роль, количество, заметка —
  `ChildContent`, «Роль» — `CastNpcDialog` со `ScenarioId`. Добавить: «Из библиотеки» (`CatalogPickerModal` по
  `ICharactersApi.ListAsync(Npc)` без уже занятых), «Быстрый» (`QuickNpcModal` со `ScenarioId` и эпохой сценария),
  «Новый» (`CreationLinks.Create(Npc, null, id)`; «Назад» оттуда — на вкладку НПС).
- **Прегены** — карточки, «Из библиотеки» — копия заготовки (без сценария), «Новый» — создание прегена со `scenarioId`;
  забронированного убрать нельзя (метка, кнопки нет).
- `CastNpcDialog` — одно окно на «В сценарий» с карточки `/npcs` (`CharacterSummaryCard.OnCast`; выбор только из
  сценариев с `CanEdit`, переделка помечена, «уже занят» подписан) и на «Роль» в составе.
- Длинные метки (место действия, занятие НПС, «Сценарий «…»») — `max-w-full whitespace-normal`: `cm-badge` не
  переносится, и на 390px такая метка раздвигала страницу вбок.

## Импорт и экспорт JSON (T2.5d)

- «Импорт JSON» — в панели фильтров `/scenarios` (только с `CanCreate`; в шапке на телефоне помещаются две кнопки),
  окно `ScenarioImportModal` по образцу `CatalogImportModal`: файл уходит на сервер как есть, «Проверить» (пробный
  прогон), потом «Импортировать»; «Название копии» — необязательно. Отчёт — `ScenarioImportReportView`: итог и
  счётчики, общие предупреждения, сначала ошибки и предупреждения строк, «Все строки файла» — под раскрытием. Ошибка
  хоть в одной строке — не записано ничего (сервер откатывает транзакцию). После записи — «Открыть сценарий».
- «Экспорт JSON» — ссылка в шапке рабочего места на `GET …/export` с `download` (Blazor её не перехватывает), видна
  всем, кто видит сценарий. Формат и правила — [Server/Scenarios/CLAUDE.md](../../CampaignManager.Server/Scenarios/CLAUDE.md).
- Импорт «Среди древних деревьев» на Neon идёт ~10 с — кнопки на это время выключены (`Busy`).

## Подписи

Слова — `Core/Scenarios/ScenarioText` (вид факта, роль НПС, вид проверки — одна таблица, в v1 вид факта переводился
трижды); разметочные — `ScenarioLabels` (цель проверки, сложность «Трудная»/«Чрезвычайная» через `CheckRules.DifficultyLabel`,
тон роли). Эпоха — `CatalogText.Of(Era)`; современной эпохи в данных нет, но в форме она есть (как у кампаний).

## Проверка

На ветке Neon `dev` под dev-Хранителем — копия «Среди древних деревьев» через API (`[T2.5a] Копия «Среди древних
деревьев»`: 20 локаций, 37 проверок, 6 фактов, 6 раздаток, 2 твари, 5 предметов, 18 НПС), перенесённые сценарии не
правились. 1366×1024 и 1024×1366: правка локации (адрес, описание, перенос на верхний уровень), проверки (сложность и
текст; новая — по характеристике), раздатки (пометка Хранителя), состава НПС (роль и количество, «Убрать», «Из
библиотеки»), текста, шапки с конфликтом и «Перечитать», преген из библиотеки, «В сценарий» на `/npcs`, `/scenarios/new`,
`/scenarios/{id}/edit`. 390×844 — все вкладки и выбор из справочника без прокрутки вбок; игроку — «Нет доступа» и 404/403
API. T2.5d — импорт через окно (пробный прогон, запись, отчёт с ошибками строк) и экспорт на 1366×1024 и 1024×1366, копии
`[T2.5d] …` удалены. Тесты UI — `UI.Tests/ScenarioTests` (выбор из справочника, дерево, адреса).
