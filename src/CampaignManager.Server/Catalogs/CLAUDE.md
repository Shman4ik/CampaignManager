# Catalogs (сервер) — справочники

Навыки, профессии, оружие, заклинания, книги, предметы, бестиарий: **один сервис и один набор
эндпоинтов** на все (`CatalogService<TEntity, TDto>`), своё у справочника — `Stores/*Store.cs`
(`CatalogStore<TEntity, TDto>`). Сделано в T2.1. UI — [UI/Catalogs/CLAUDE.md](../../CampaignManager.UI/Catalogs/CLAUDE.md).

## Где что

| Слой | Файлы |
|---|---|
| `Contracts/Catalogs` | DTO (`SkillDto`…`CreatureDto`, общий `CatalogItemDto`), `CatalogList<T>`, `CatalogFile<T>`, отчёт импорта, `CatalogsRoutes`/`CatalogRoute`, `ICatalogApi<T>` |
| `Contracts/Platform/ApiProblem.cs` | `ApiProblemCodes` (`stale`, `duplicate`, `in-use`, `invalid`, `version-required`) и `ApiException` |
| `ApiClient/Catalogs` | `CatalogApiClient<T>` и по клиенту на справочник; отказ — `ApiException` с кодом (`ApiResponses`, `withCode`) |
| `Server/Catalogs` | `CatalogsModule` (эндпоинты), `CatalogService`, `CatalogStore`, `Stores/`, `CatalogAuditInterceptor` |
| `Server/Platform/ApiProblem.cs` | `ApiProblemException` и обработчик: 400/409/428 с кодом; `DbUpdateConcurrencyException` → 409 `stale` |
| `Core/Catalogs` | `OccupationSeed` (сид профессий), `CatalogText` (подписи), разборщики |

Фонотека (T2.8) — восьмой справочник на том же сервисе: `MusicTrackStore` в модуле Music регистрируется
публичными `CatalogsModule.AddCatalog`/`MapCatalog`. У трека нет кода книги — хранилище говорит `HasCodes => false`,
и сервис присланный код не читает, импорт ищет только по имени. См. [Music/CLAUDE.md](../Music/CLAUDE.md).

## API (`/api/v1/catalogs/{skills|occupations|weapons|spells|books|items|creatures|music}`)

- `GET` — список целиком и `canEdit`. **ETag** — хеш id и версий (`xmin`) строк, прав и сборки контрактов:
  `Cache-Control: private, no-cache`, браузер перепроверяет и получает 304 без тела. Сборка в ETag — затем,
  чтобы после выкатки браузер не показывал по старому ETag ответ без нового поля DTO (на этом обожглись).
- `POST` — создать; `PUT {id}` с **`If-Match: "версия"`** — правка; без заголовка — 428, чужая версия — 409
  `stale` (и до записи — сверкой, и в самой записи — `xmin`). `DELETE {id}`.
- `GET export` — файл обмена (`{ "catalog": "weapons", "items": [...] }`, `Content-Disposition: attachment`).
- `POST import?overwrite=&dryRun=` — тело — файл обмена как есть. Ключ записи — `code`, без него — имя без
  учёта регистра (и «ё»). Найденная — пропуск или перезапись; ошибка записи не останавливает остальные
  (строка отчёта `Failed`). Пробный прогон проходит те же проверки и ничего не пишет. Файл другого
  справочника — 400. Ссылки по id из другой базы (навык оружия, слоты профессии) импорт ищет по имени
  (`skillName`, `optionNames` в DTO); картинки другой базы — пропускаются с предупреждением.
- `POST sync?dryRun=` — «Синхронизировать с правилами», только где есть сид (сейчас профессии). У обновлённой записи
  строка отчёта называет, что изменилось («изменено: Средства: до», «без изменений») — `CatalogChanges`: снимок полей
  DTO до и после, подписи колонок в словаре там же (новое поле DTO без подписи покажется своим именем). Тот же
  отчёт — у импорта с перезаписью.
- Цена предмета — `items.price` (numeric(12,2), доллары 1920-х, null — не указана); показ — `Core.Catalogs.PriceText`.

Тело читается сгенерированным контрактом вручную (`BodyAsync`): параметр-тело обобщённого типа в
минимальном API роняет анализатор (AD0001).

## Права

`AccessPolicy.ForCatalogAsync`: читать — любой вошедший, писать и удалять — Хранитель (и админ). **Каждый
метод записи сервиса зовёт `Demand`** (создать, правка, удаление, импорт, синхронизация) — в v1 четыре
справочника не проверяли права вовсе, а «Изменить/Удалить» тварей, навыков и профессий видели игроки.
Группа эндпоинтов — `RequireAuthorization()`: аноним — 401, игрок на запись — 403.

**Игрок не получает статблок твари** (решение владельца 2026-10-03, #175): `CatalogService.ListAsync` для читателя без
`CanEdit` прогоняет строки через `CatalogStore.ForReader`; `CreatureStore` заменяет `Statblock` пустым, оставляя имя,
тип, картинки, источник и «Описание». Это и список, и файл экспорта (он строится из списка); ETag у игрока и Хранителя
разный (в него входит `canEdit`). Новое секретное поле справочника — туда же, не в интерфейс.

## Запись

- Общее (`CatalogService.ApplyAsync`): имя обязательно, до 200 знаков, **уникально без учёта регистра** —
  проверка до записи даёт понятный 409 `duplicate` («Оружие «…» уже есть в справочнике»), индекс
  `lower(name)` ловит гонку (тоже 409). Код принимается **только при создании** (импорт, сид) и должен
  быть кодом справочника (`weapon.…`, нижний регистр); правка код не меняет — выданный код постоянен.
- Источник (`source`) — страница книги; null — самодельное. Пустой источник в импорте не стирает прежний.
- Правка только детей (слоты, заклинания книги, картинки) **сдвигает версию корня**: сервис помечает
  корневую строку изменённой, иначе `If-Match` не сработал бы.
- Дети с составным ключом (`book_spells (book, ord)`, `creature_images (creature, ord)`) правятся на месте
  по порядку, лишние удаляются; удалить и добавить строку с тем же ключом в одном сохранении EF не даст.
  Новых детей — явный `db.Add`: у слота профессии ключ задан заранее (uuid v7), и найденный через навигацию
  у уже отслеживаемой профессии EF счёл бы существующим (UPDATE вместо INSERT, варианты падали на FK).
- Удаление занятой записи (FK `restrict`: навык у оружия или профессии, тварь в сценарии) — 409 `in-use`.

### По справочникам

- **Оружие**: строки книги вводит человек, **числа для боя разбираются здесь, один раз при записи**
  (`DamageFormulaParser`, `WeaponStatsParser`): дальность, атаки, магазин, стоимость по эпохам, урон
  дробовика по дистанциям. Присланные клиентом числа не читаются. Неразобранная строка — не ошибка
  (самодельное, «Шок»), а предупреждение в отчёте. Осечка 1–100 («00» = 100). Навык обязателен.
- **Навыки**: родитель — навык без родителя (одна ступень), не сам себе и не навык, у которого свои
  специализации. База — число 0–99 или формула `DEX/2`/`EDU`.
- **Профессии**: слот проверяется тем же правилом, что CHECK в базе (вид → какие поля); выбор — минимум два
  варианта, выбрать 1..N. Счёт навыков — `OccupationRules.ProfessionalSkillCount` (Средства и Мифы не в
  счёт), отдаётся в DTO и предупреждает, если не 8 (стр. 37). Синхронизация: апсерт сида `OccupationSeed`
  **по коду** (в v1 — по имени, и переименование в коде заводило двойника); навыки сида ищутся по коду
  справочника, а не id. Самодельные (код null) не трогаются; самодельная с тем же именем, что у книжной,
  получает её код. Хакера нет — современная эпоха не переносится.
- **Книги**: несвязанные заклинания сопоставляются со справочником при записи — **только точное совпадение**
  имени или другого названия (`SpellMatcher`); не нашлось — строка остаётся строкой книги.
- **Заклинания**: «другие названия» без самого имени и без повторов — по ним книга находит заклинание.
- **Бестиарий**: статблок — документ Core (`CmJson.Write`, версия — `Statblock.CurrentVersion`), картинки —
  `creature_images` (первая — обложка). Предупреждения, а не отказ: тварь без атак или без ПЗ сохраняется,
  но Хранитель видит, что урон или БкУ бой не бросит (`DiceFormula.IsValid`), а потерю рассудка не разобрать.

## Журнал правок

`CatalogAuditInterceptor` пишет в `cm.audit_log` **снимок «после»** (колонки корневой строки) для каждой
созданной, изменённой и удалённой записи справочника — в то же сохранение, не вторым `SaveChanges`. Автор —
`CurrentUser` (берётся при сохранении из scope: в конструкторе зависимость замкнулась бы в круг через
`CmDbContext`). Перехватчик scoped — в v1 синглтон с общим списком давал гонку. **Интерфейса истории нет**
(D6.1): «сравнить» в v1 показывал две JSON-простыни, «откатить» не работал. Перехватчики модулей
`CmDatabase.AddCmData` берёт из DI (`ISaveChangesInterceptor`).

## Тесты

`Server.Tests/Catalogs/CatalogsApiTests` через `ApiClient` на своей базе (`CatalogsApp`: Хранитель, игрок,
админ; навыки книги заведены по `SkillCodes`): игрок читает, но любая запись — 403, аноним — 401; дубль — 409
`duplicate`; устаревшая версия — 409 `stale`, без `If-Match` — 428; 304 по ETag; разбор оружия при записи;
осечка вне 1–100 — 400; удаление занятого навыка — 409 `in-use`; журнал со снимком и автором; заклинания
книги и правка только детей; статблок и предупреждения импорта; импорт с пропуском, перезаписью и пробным
прогоном; экспорт → импорт по коду; синхронизация профессий по коду, второй прогон — только обновления,
самодельная не тронута. `Core.Tests/Documents/OccupationSeedTests` — сид: все книжные профессии, у каждой 8
навыков, все имена навыков распознаются.
