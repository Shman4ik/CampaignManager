## Фонотека — справочник

Треки идут через **общий `CatalogService`** (T2.1) со своим `MusicTrackStore`: `/api/v1/catalogs/music` — список
целиком с ETag (304), создание, правка с `If-Match` (409 `stale`), удаление, `export`/`import`, журнал правок
(`audit_log`, `EntityType = MusicTrack`). Права — `ForCatalogAsync`: читает любой вошедший, пишет Хранитель
(в v1 `/music` закрывала от игрока только разметка, а импорт и пачка писали мимо проверок).

- `MusicTrack` наследует `CatalogEntry`, но **кода книги и источника у трека нет**: `Code` и `Source` модель не
  отображает (`Ignore`), колонок нет. Хранилище говорит `HasCodes => false` — сервис не читает присланный код,
  импорт ищет трек только по имени. `CatalogsModule.AddCatalog`/`MapCatalog` — публичные ради этого модуля.
- Имя уникально без учёта регистра (индекс `lower(name)` из T1.2) — 409 `duplicate`, «Трек «…» уже есть».

## Источник трека — не трогать

- **Ровно одно из двух**: `youtube_id` или `file_id` (CHECK в базе, 400 до неё).
- YouTube: можно прислать ссылку любой формы (watch, youtu.be, embed, shorts, live, music.youtube.com) —
  `YouTubeVideo.TryParseId` достанет id; не ролик — 400. Встраиваемость сервер не проверяет: её видно только в
  плеере (ошибка 101/150). Проверить ссылку до занесения — oEmbed `https://www.youtube.com/oembed?url=…&format=json`
  (200 — ролик жив, но о встраивании не говорит). Каналы «Исполнитель - Topic» встраивание обычно запрещают.
- Файл: **только загруженный звук** (`storage_key` есть, `content_type` — `audio/*`). Внешний адрес не годится:
  он отдаётся переходом на чужой origin, а Web Audio на элементе с чужого origin без CORS даёт **тишину** —
  громкость же на iPad есть только через Web Audio. Картинка — 400. Файл из другой базы (импорт) — строка отчёта
  `Failed`: «загрузите звук заново».
- Отдача файла — модуль Files: свой origin, Range потоком (206), `immutable`. Сам модуль Music файлов не отдаёт.
- Удаление трека файл не удаляет: он становится сиротой и уходит уборкой сирот (Files).

## Теги

`MusicTags.Normalize`: trim, нижний регистр, «ё» → «е», пробелы схлопнуты; повторы выброшены, список отсортирован.
Без этого «Бой», «бой » и «бой» расходились по трём пулам. Не больше 30 тегов, тег — до 40 знаков (400).

## Закреплённые настроения

`GET|PUT /api/v1/music/pinned-tags` — кнопки ряда «Настроение» на панели плеера. Своя настройка: строка
`cm.user_preferences (user_id, 'music.pinnedTags')`, id из сессии, чужой не принимается.

- Значение — JSON-массив строк в порядке Хранителя. **Читаются и строка через запятую** — так ключ хранил v1
  (перенос T1.3 кладёт значения v1 как есть).
- Запись — upsert одним SQL (`insert … on conflict do update`): другие ключи и устройства не затрагиваются.
- Пустой список — строка удаляется, и снова действуют умолчания `MusicDefaults.PinnedTags`
  («бой», «погоня», «напряжение», «расследование», «ужас», «спокойствие»); ответ говорит `isDefault`.
- Ключ — `PreferenceKeys.MusicPinnedTags` модуля Profile (T2.9): общий API настроек `/api/v1/profile/preferences`
  видит ту же строку. Эндпоинт фонотеки — типизированный: нормализует теги, проверяет пределы, отдаёт умолчания.

## Пул сцены — стык с T2.5b и T2.6

`GET /api/v1/music/pool?tag=…&tag=…&track=<id>` — треки, у которых есть хоть один из тегов, плюс прибитые явно.
Правило одно — `Core/Music/MusicPool`: его же зовёт плеер в браузере над загруженной фонотекой. Сервис грузит
фонотеку целиком (сотня строк) и фильтрует правилом Core — SQL-копии условия нет.

Музыка локации — **T2.5b, подключена** (запись — `PUT /api/v1/scenarios/{id}/locations/{locationId}/music`, Scenarios): `scenario_locations.music_tags` + `location_tracks` → `MusicPool.Of(tags, trackIds)`;
в UI — `<MusicPoolButton Pool=… Label="имя локации" />`, на сервере (экспорт сценария T2.5d, мобильное
приложение) — `MusicService.GetPoolAsync`. Кнопка настроения боя и погони (T2.6) — тот же компонент с
`MusicPool.Of(["бой"])`.
