# Profile (Server) — личный кабинет

Модуль T2.9: `ProfileModule` (`AddProfileModule`/`MapProfileApi`), `ProfileService`. Маршруты, DTO и
`IProfileApi` — `Contracts/Profile`, клиент — `ApiClient/Profile`, страница — [UI/Profile/CLAUDE.md](../../CampaignManager.UI/Profile/CLAUDE.md).
Таблицы — `users`, `user_preferences`, `keeper_applications` (+ чтение `campaign_members`, `characters`) из T1.2;
миграций модуль не добавил. Знание перенесено из `Features/Profile/CLAUDE.md` v1.

## API

| Метод и адрес | Что |
|---|---|
| `GET /api/v1/profile` | кабинет одним запросом: имя, почта, роль, число кампаний, сыщиков и псевдонимов, последняя заявка, `CanApply` |
| `PUT /api/v1/profile/name` | `{ displayName, replaceAliases }` — сменить имя |
| `POST /api/v1/profile/keeper-application` | `{ message }` — заявка на Хранителя |
| `GET /api/v1/profile/preferences` | все мои настройки: ключ → JSON |
| `PUT/DELETE /api/v1/profile/preferences/{key}` | записать одну настройку (тело — любое JSON-значение) / вернуть по умолчанию |

Всё — `.RequireAuthorization()` и **только про себя**: id в адресах нет, сервис берёт пользователя из
`CurrentUser` (Access, строка «Профиль»). Отказы по смыслу — `ApiProblemException` (Platform): 400 `invalid` —
форма, 409 `conflict` — заявку подать нельзя.

## Имя

- **Источник истины — `users.display_name`**, и показывается оно отовсюду из базы: `/api/v1/me` (меню), кампании
  (`PublicNames`), админка. В v1 имя жило ещё в claim куки и в копиях `CampaignPlayer.PlayerName`, отсюда
  `RoleClaimsTransformation`, сброс `UserClaimsCache` и перезагрузка страницы после сохранения — в 2.0 всего этого нет.
  Вход имя **не перезаписывает** (`UserDirectory.SignInAsync` берёт `name` провайдера только для новой строки).
- Проверки: не пусто после `Trim`, не длиннее `ProfileLimits.DisplayNameLength` (64, как в v1), **без «@»** — имя
  видят другие, а имя, похожее на почту, сервер другим всё равно не показывает (`PublicNames`). Перенесённым
  пользователям с именем = почте кабинет как раз и даёт его сменить.
- Два игрока с одинаковым именем — норма: людей различает id, а не имя (в v1 — почта).

## Псевдонимы в кампаниях — «заменить и в кампаниях»

- Имена в кампаниях **нарочно разные** («Дима» в одной, полное имя в другой), поэтому галочка по умолчанию
  **выключена** — решение v1 сохранено.
- В 2.0 псевдоним — `campaign_members.display_name`, `null` значит «имя из профиля». Поэтому «заменить» — это
  **сбросить** псевдонимы (`display_name = null`) во всех моих кампаниях, а не переписать копии новым именем: дальше
  кампании идут за профилем и следующую смену имени увидят сами. Имя и сброс — одна транзакция.
- `AliasCount` в кабинете — сколько кампаний затронет галочка; без псевдонимов галочки нет вовсе.

## Заявка на Хранителя

- Подаёт любой вошедший **игрок**. Хранителю и администратору — 409 («уже Хранитель»). Заявка на рассмотрении — одна:
  проверка в сервисе и частичный уникальный индекс `keeper_applications_one_pending` (две вкладки → 409, а не 500).
- Текст — по желанию (в v1 кабинет слал пустой), до `ProfileLimits.ApplicationMessageLength` (1000, как CHECK в базе).
- После отказа можно подать снова (`CanApply`), комментарий администратора виден в кабинете. Рассмотрение — модуль
  [Admin](../Admin/CLAUDE.md).
- Карточки «Стать Хранителем» на главной нет (в v1 её убрали: «скрыть навсегда» и потом не найти) — статус и кнопка
  только в кабинете.

## Настройки

- **Строка на ключ** (`user_preferences (user_id, key)`): запись одного ключа — upsert одним SQL
  (`insert … on conflict do update`), другие ключи и другие устройства не затрагиваются. В v1 весь словарь писался
  целиком, кэшировался на 30 секунд и терял записи правкой «на месте».
- Ключ — `PreferenceKeys.IsValid`: латиница, цифры, `.`, `-`, `_`, с буквы, до 64 символов; значение — любой JSON
  до 8 КБ. Известные ключи — константы `PreferenceKeys` (`ui.syncLastCharacter`, `music.pinnedTags`).
- **Значения из v1 — JSON-строки** (`"true"`, а не `true`): v1 хранил `Dictionary<string,string>`, перенос T1.3
  положил их как есть. Читатель ключа принимает обе формы.
- Экрана настроек в кабинете пока нет: читатели обоих ключей — нижняя навигация (M2) и фонотека (T2.8); до них
  флажок ничего бы не делал.
