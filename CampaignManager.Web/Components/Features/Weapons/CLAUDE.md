# Weapons Feature

Master weapon catalog (independent entity). Источник правды по данным — таблица XVII
«Оружие» книги правил CoC 7e (стр. 399–402).

## Key Services
- `WeaponService(dbContextFactory, IMemoryCache, logger)` — CRUD + cached lookups.
  `GetAllRangeWeaponsAsync()` фильтрует уже загруженный список в памяти: `WeaponType` —
  не набор флагов, объединить типы в одно значение нельзя.
- `WeaponStatsReader` — **единственная точка, где спрашивают у оружия число**
  (`AmmoCapacity`, `TryMalfunctionThreshold`, `BaseRangeMeters`, `Attacks`, `Range`,
  `Ammo`, `Cost`, `MaxShotsPerRound`, `AttacksDisplay`, `RangeDisplay`). Порядок всегда
  один: разобранное поле → разбор строки на лету → пусто. Средняя ступень — ветка
  совместимости со старыми копиями в JSONB листов: они записаны до появления разобранных
  полей и несут только текст. Не читай `weapon.Ammo`/`weapon.Malfunction` напрямую.
- `WeaponFactory` — `CopyForCharacter(catalogWeapon)` и `FillParsedStats(weapon)`.

## Key Models
- `Weapon : BaseDataBaseEntity, INamedEntity`.
- `WeaponDamageInfo`, `RangeDamageEntry` — разобранный урон (`DamageInfo`, JSONB).
  Заполняется `Utilities/Services/DamageFormulaParser` из текстового поля `Damage`
  и хранит внутри `RawText` + `IsParsed`. **Это образец для любого нового разобранного
  поля**: типизированные данные рядом со строкой правил, а не вместо неё.
- `WeaponRangeInfo` (`RangeInfo`), `WeaponAttacksInfo` (`AttacksInfo`),
  `WeaponAmmoInfo` (`AmmoInfo`), `WeaponCostInfo` (`CostInfo`) — то же устройство для
  остальных колонок таблицы XVII. Все четыре — JSONB, заполняет
  `Utilities/Services/WeaponStatsParser`.
- `WeaponType` — разделы таблицы XVII. Значения нумеруются подряд, `[Flags]` на нём быть
  не должно: раньше он там стоял, и `Pistols | Rifles` молча давал `Shotguns`.

## Аддитивная схема: строка + разбор

Строковые поля (`Damage`, `Range`, `Attacks`, `Ammo`, `Malfunction`, `Cost`) **остаются** —
это исходный текст правил и escape-hatch для самодельного оружия Хранителя. Разобранные
объекты живут рядом, а не вместо них. Отсюда два следствия:

- Старые JSONB-листы обязаны читаться без изменений: новые свойства = `null`, а
  `WeaponStatsReader` разбирает их строки на чтении. Миграция данных не блокирует выкат.
- Меняешь строку — пересобирай разобранное поле (`WeaponFactory.FillParsedStats`),
  иначе в форме покажется старый разбор. `Damage` тянет за собой ещё и
  `DamageInfo.RawText` (и `RangeDamages[].Damage.RawText` у дробовиков).
- **Не добавляй вычисляемые свойства на `Weapon` без `[JsonIgnore]`** — этот тип целиком
  сериализуется в JSONB листов персонажей.

## Данные каталога
- `Skill` хранит **каноническое** имя навыка из `games."Skills"` («Стрельба (пистолет)»),
  а не сокращение книги («Стрельба (П)»); `SkillId` — ссылка на ту же запись.
- **У `SkillId` намеренно нет FK и навигационного свойства.** Тот же тип лежит внутри
  JSONB листов, где ограничение всё равно не действует, а удаление навыка не должно
  ронять каталог оружия. Каноническое имя продолжает храниться денормализованно в `Skill`.
- `MalfunctionThreshold` (`int?`) — порог осечки числом; `Malfunction` остаётся строкой,
  потому что в старых JSONB-листах встречается «00» (это 100 на процентных костях).
- `Is1920` / `IsModern` / `IsRare` — колонка «Встречается» книги. Редкость **ортогональна**
  эпохе: «1920-е, редко» — это `Is1920` вместе с `IsRare`. Раньше «Редкое» лежало текстом
  в `Notes` и даже в `Cost`.
- `Notes` — только настоящие примечания. Эпоха, редкость и «(пронз.)» дублировались там
  и вычищены: у них есть свои поля.
- `Damage` пишется как в книге: `1d6 + БкУ`, кости в нижнем регистре, пробелы вокруг `+`.
- Законно неразобранными остаются только те ячейки, что и в книге записаны словом:
  «Варьирует» у боезапаса электрошокера, «Шок» в уроне.

## Копия оружия в листе персонажа

`Character.Weapons` — это **копии**, а не каталожные экземпляры. Копия несёт собственный
`Id` и обязательный `CatalogWeaponId` (у каталожной строки он `null`; у самодельного
оружия Хранителя — тоже `null`).

**Никогда не клади каталожный экземпляр в лист.** `WeaponService` держит список в
`IMemoryCache`, общем для всех пользователей: правка патронов на листе мутировала бы
справочник у всех сразу. Именно этим и болел `WeaponComponent.SelectWeapon` до
`WeaponFactory.CopyForCharacter`.

## Страница каталога `/weapons`

Каждая колонка таблицы XVII — **отдельный столбец**, строка занимает одну строку:
`Название · Тип · Навык · Урон · Дист. · Атаки · Боезапас · Осечка · Цена · действия`.

- **Раскрытая строка не повторяет колонки.** В ней только то, чего в столбцах нет:
  разбивка дальности, ёмкость магазина, примечания. Добавляешь колонку — убирай её из
  раскрытия, иначе вернётся то самое дублирование, из-за которого страницу переделывали.
- **Эпоху в строке показывает `ShowEra`** (`is1920Filter == isModernFilter` на странице).
  При фильтре по одной эпохе метка стоит у каждой строки и не различает ничего — тогда
  она уезжает в раскрытие. Редкость и «пронз.» рисуются всегда: они действительно редкие.
- Плотность задаёт `WeaponsListView.razor.css`, а не утилиты в разметке: `.cm-table td`
  из design-system.css перебивает одиночный класс Tailwind по специфичности. Селекторы
  идут через `::deep` — строки рендерит дочерний `WeaponTableRow`.
- Таблица живёт от `lg` (1024 — портрет iPad), ниже — карточки. В портрете таблица
  прокручивается вбок внутри своего `overflow-x-auto`, страница вбок не едет.
- Кнопки строки — иконки `cm-btn-sm cm-btn-icon` 36×36 с `aria-label`; подписей нет,
  подсказок по наведению тоже (на планшете их не бывает).
- `UnparsedMark` — значок «разобрать не удалось» рядом со значением.
